## 0. Findings in short

1. **Grammar.**
   - OSL LPEs are regular expressions over *events*. Each event is a label sequence `type scatter custom... STOP`.
   - Karma fixes the custom positions as `<type scatter 'object/light tag' 'bsdf label'>`.
   - Karma has no `S`/`s`: every specular event is `G`.
   - Karma adds `A` (albedo), `B` (background), a leading `!` (invert) and the prefixes `unoccluded;`, `shadow;` and `holdout(s);`.
   - Karma's standard AOV table has 26 LPE RenderVars (`karmautils.py:58-95`). Without the `unoccluded;`/`shadow;` prefixes, which add outputs but no automaton states, they are 18 distinct expressions.
   - Per-light splits are generated by the LOP, not by the renderer.
2. **Runtime representation: one product DFA for all bound expressions, as OSL does.**
   - Each path carries **one `uint16_t` state**: 2 bytes.
   - An event costs one table lookup: `next[state * classCount + symbolClass[symbol]]`. Final states carry a short list of output ids.
   - Prototype sizes:

     | Expression set | Minimized states | Symbol classes | Table |
     |---|---|---|---|
     | Karma's set: 20 rules, 18 distinct expressions | 57 | 18 | 2 KB |
     | 74 rules (the same, with each lighting rule split for 3 light tags) | 114 | 21 | 4.8 KB |
     | 30 rules (Karma + toon presets with object/light tags and labels) | 316 | 39 | 25 KB |

     All random-path checks against the NFA matched.
3. **Precomposed events.** The compiler collapses each event's label sequence into one transition, so the runtime never sees labels. Symbols that no expression distinguishes fall into one class. That class also tells the integrator **when a lobe split is needed at all**: with only beauty and light groups, every scattering event is one class, so no split and no extra work.
4. **Per-lobe NEE split.**
   - `evalClosure` gets an optional per-slot output. Slots are the distinct (symbol class, light-multiplier kind) pairs of the closure's lobes, assigned once per hit, 6 at most. The cost is one indexed `Spectrum` add per evaluated lobe.
   - Each slot gives its own final state. The shadow entry carries the parts, merged by final state.
5. **BSDF continuation: stochastic class selection.**
   - Nova's one-sample mixture weight `f_total/p_mix` (`closure.h:sampleClosure`) cannot be given a single event class without bias per component.
   - Proposal: choose slot k with q_k = lum(f_k)/lum(f_total) at the sampled direction, and weigh it by `f_k/(p_mix q_k)`.
   - This is unbiased per component and keeps the cross-lobe MIS. It preserves the beauty's luminance per sample, and **Σ components == beauty per sample**.
   - It costs one random number (a new stream block) and no extra evaluation, because the multi-lobe path already calls `evalClosure`.
6. **Accumulation.**
   - Contributions are added straight into per-output film sums. Tiles are exclusive to one thread per wave, so there are no atomics on the CPU.
   - The NaN filter moves from the per-path total (`renderWave`) to each contribution, for the beauty too, so the invariant holds.
   - Filter importance sampling means AOVs need no filter weights: a pixel is the plain mean of its samples, as for the beauty.
7. **Hydra and husk.**
   - Today `HdNovaRenderBuffer::ResolveAovSource` maps only `C.*`/`C.*[LO]` to the beauty and leaves every other LPE clear.
   - M6 compiles all LPE bindings into one program per render (`HdNovaRenderDelegate::SetAovBindings`).
   - `_RenderLoop` copies every bound AOV every pass. With 20-80 AOVs at 4K that copy dominates, so non-displayed AOVs should be copied lazily.
   - husk already writes multi-part EXR from the buffers. `nova_cli`'s `writeExr` writes one part per AOV.
8. **Cost estimate.**
   - Below 1 % with only beauty or light-group expressions: bit-identical beauty, no splits.
   - About 2-5 % CPU time with Karma's standard component set (~20 AOVs): table lookups, slot adds and film writes, against a measured ~700 ns per ray and thread.
   - Film memory: 12 B per pixel and output (1080p × 20 outputs ≈ 0.5 GB).
9. **Utility AOVs.**
   - Nova has `depth`/`cameraDepth`, `normal`, `albedo` (all-lobe, the denoiser guide), `primId` and `instanceId`. All come from one pixel-center first-hit ray (`wavefront.cpp:renderFirstHitAovs`).
   - Missing: P (world/camera), Ng, `elementId` (needs a triangle→face map), primvar AOVs (UV), motion vectors and velocity, facing ratio, and Karma's LPE `albedo` (`CDA`, an A event).

## 1. The LPE grammar (production subset)

### 1.1 Events and labels

| Symbol | Kind | Meaning | Nova source |
|---|---|---|---|
| `C` | type | camera (every LPE starts with it) | path start |
| `R` / `T` | type | surface reflection / transmission | sampled or evaluated lobe; side from the geometric normal |
| `V` | type | volume scatter | M8 |
| `L` | type, terminal | light source (UsdLux, later mesh lights) | NEE, BSDF ray hitting a light, camera-visible light, escape to dome/distant |
| `O` | type, terminal | emissive object (not a light) | `ClosureList::emission` |
| `B` | type, terminal | background: a ray that left the scene (alpha planes, `!C<TG>*B`) | escapes |
| `A` | type, terminal (Karma) | albedo of the preceding scattering event (`CDA`) | closure albedo per class |
| `D` / `G` | scatter | diffuse / glossy | lobe |
| `S` / `s` | scatter (OSL only) | singular / straight (pass-through) | Karma maps every specular event to `G`; Nova follows (1.4) |
| `x` | scatter | "none" (the parser's alias for `NONE`; lights and `C` have no scatter) | |
| `'name'` | custom label | object/light tag or BSDF label | `karma:object:lpetag` / `karma:light:lpetag` / material `inputs:karma:lpetag` / lobe label |

### 1.2 Event syntax

Per OSL's `lpeparse.cpp`, `Parser::buildStop`/`parseGroup`/`parseSymbol`:
- **An event is a label sequence.** The renderer pushes `type, scatter, custom1, custom2, ..., STOP`.
  - `<RD>` expands to `R D [any custom]* STOP`.
  - A position left out inside `<>` is the wildcard `.` (anything but `STOP`).
  - Unnamed trailing customs are matched by `[any custom]*`.
- **Bare symbols are shorthands.**
  - `D` = `<.D>`, `R` = `<R.>`, `L` = `<L.>`.
  - A bare `'tag'` means "first custom label is `tag`", i.e. `<..'tag'>`. Karma's `C'brick_wall'.*L` is exactly this.
- **Custom labels are positional.** Karma documents `<event_type scatter_type['tag'['bsdf_label']]>`: position 3 is the object or light tag, position 4 the BSDF label.
  - So the coat preset is `C<...'coat'>.*L`.
  - Light groups are `<L.'key'>`.
  - Nova must push **a placeholder tag** (a label no expression can name) for untagged objects, so that BSDF labels stay at position 4.
- **Operators:**

  | Operator | Meaning |
  |---|---|
  | `.` | any one event |
  | `*` | zero or more |
  | `+` | one or more |
  | `{n}`, `{n,m}`, `{n,}` | repetition counts |
  | `\|` | alternation |
  | `( )` | grouping |
  | `[...]` | set (any of the events listed) |
  | `[^...]` | negated set (a blacklist at one label position) |

  - Inside `<>`, only symbols, `.` and sets are allowed; there is no repetition and no nested `<>`.
  - OSL has no `?`. `!` is not part of OSL's parser; it is handled at the output (OSL `AovOutput::neg_color`: 1 − v).

## 2. Compiling and running LPEs

### 2.1 Compile pipeline (host, once per AOV-binding change)

1. **Parse** each expression with OSL's grammar (1.2) plus Karma's prefix and `!` handling. Errors are reported once per AOV, and that AOV stays at its clear value.
2. **Build a Thompson NFA over labels.** Each expression's accept state is tagged with its output id (OSL: `lpexp::Rule`, one NFA for all rules, `AccumAutomata::compile`). Wildcards are blacklists (`Wildexp`), so the label alphabet stays open (unknown tags match `.`).
3. **Run subset construction at event granularity** (Nova-specific; OSL steps per label).
   - The event alphabet is finite and known at compile time: {C, R, T, V, L, O, B, A} × {D, G, x} × (tags named in any expression + "other/placeholder") × (labels named + "none/other").
   - A DFA state is an ε-closed NFA state set at an event boundary. Its transition on an event follows the event's whole label sequence.
   - The result is the product DFA for all expressions. OSL also builds one product automaton (`ndfautoToDfauto`).
4. **Minimize** (Moore/Hopcroft). The initial partition is the set of outputs per state, and the dead state is kept. OSL only merges identical states (`DfAutomata::removeEquivalentStates`).
5. **Compress the alphabet.** Event symbols with identical transition columns form one class: `symbolClass[]`, then a dense `next[state][class]`.
6. **Per-state output lists.** Each entry is an output id plus flags (`unoccluded`, `shadow`, `!`).

| Prototype case | Expressions | Event symbols | Subset states | Minimized | Classes | `next` table |
|---|---|---|---|---|---|---|
| beauty only | 1 | 14 | 5 | 3 | 3 | 18 B |
| Karma's set: 18 distinct expressions + beauty `unoccluded;`/`shadow;` (labels coat/sss/sheen known) | 20 | 23 | 73 | 57 | 18 | 2 KB |
| the same, each lighting rule split for 3 light tags | 74 | 92 | 130 | 114 | 21 | 4.8 KB |
| Karma's set + 10 toon/tag presets | 30 | 96 | 388 | 316 | 39 | 25 KB |

- At most 6 outputs per final state for Karma's set, 12 with three light tags.
- The 6 prefixed diffuse variants of Karma's full table (26 RenderVars) repeat expressions already listed, so they add outputs but no states.

Scattering classes with Karma's set: {RD, RD'sss', RD'sheen'}, {RD'coat'}, {RG,...}, {RG'coat'}, {TD,...}, {TG,...}. Unreferenced labels collapse automatically. With beauty plus light groups, *all* R/T events are one class.

Worst cases are exponential, as for any product DFA. **Guard:** if the minimized DFA exceeds 65 535 states or a table budget (1 MB), split the outputs greedily into groups, each with its own DFA (k `uint16` states per path). No realistic preset set comes near this.

### 2.2 How renderers apply them

- **OSL's runtime** (`accum.h`/`accum.cpp`):
  - An `Accumulator` holds an `int` state and an output array. `move(type, scatter, customs, STOP)` steps label by label; a negative state is "broken", meaning the branch can be cut.
  - `accum(color)` adds to every rule of the current final state.
  - Branches (light samples) use `pushState()`/`popState()`. `test()` checks whether a move can still match.
  - Transitions are sorted per state with a wildcard fallback (`DfOptimizedAutomata::getTransition`, binary search on ustring pointers).
  - Nova replaces label stepping and binary search with precomposed events and a dense table, which suits the GPU better.
- **Cycles** (no LPE, from memory):
  - `BsdfEval` keeps `sum`, `diffuse` and `glossy` spectra. The ratios diffuse/sum and glossy/sum become per-path pass weights at the first bounce, and each later contribution is split by them.
  - This *fractional* split only works because the passes depend on the first bounce alone. General LPEs need discrete states, hence 2.5.
- **Karma and Arnold**: closed source. Karma's documented behaviour is section 1.

### 2.3 Runtime representation for Nova

`core/film/lpe.h`, `NOVA_HOST_DEVICE`, a POD view over flat arrays (`std::vector` on the host, device buffers in M10):

```cpp
namespace nova::lpe {
using State = uint16_t;          // 0 = dead (absorbing, no outputs): the path skips LPE work
struct Program {                 // read-only, shared by all threads
    uint32_t stateCount, classCount;
    const State *next;           // [state * classCount + cls]
    const uint8_t *symbolClass;  // [symbol] -> cls (<= 256 classes)
    const uint32_t *outBegin;    // [state + 1] prefix sums into outs
    const uint16_t *outs;        // output id | flags (unoccluded, shadow)
    State start;                 // state after the C event
    uint16_t tagCount, keyCount; // symbol = ((type * 3 + scatter) * tagCount + tag) * keyCount + key
    const uint8_t *lobeClass;    // [side][tag][lobe key] -> cls, for slot assignment (2.5)
    const uint8_t *hasAlbedoOutputs; // [state]: some E(k) -> A step reaches outputs (skip A work otherwise)
};
NOVA_INLINE State step(const Program &p, State s, uint32_t sym) { return p.next[s * p.classCount + p.symbolClass[sym]]; }
}
```

- **Per-path state:** `WaveQueues::lpeState`, `std::vector<uint16_t>`, 2 bytes per path. It is set to `start` in `generateCameraRays`.
- **Symbols are computed, not stored:**
  - the object tag id lives on `MeshRecord`, the light tag id on `LightData` (a `uint16_t` each, remapped when the program changes);
  - the lobe key (scatter + label + forced-T) lives on `Lobe`, a `uint8_t` obtained by packing the existing `diffuse`/`sss` bools into a flags byte, so `sizeof(Lobe)` stays the same.
- **No virtual calls.** Templates on `LpeMode {Off, On}` keep the off path free of registers and branches on the GPU. The CPU uses a runtime flag in `ShadeContext`.

### 2.4 Where events and contributions happen

Notation: s = the path's state before the hit; `E(k)` = the scattering event of slot k on the given side; `L(i)` = light i with its tag.

| Site (`core/integrator/wavefront.cpp`) | Events appended | Value |
|---|---|---|
| `gatherLights`, depth 0, `cameraAreaLight` | start → `L(i)` (needs the light index from `nearestCameraLight`) | beta · Le |
| `gatherLights`, depth 0, miss, `cameraEnvironment` | per visible light: start → `L(i)`; plus start → `B` | beta · Le_i; beta (S5) |
| `gatherLights`, depth > 0, `areaLightsAlongRay` | per crossed light: `lpeState[p]` (already holds the scattering event) → `L(i)` | beta · Le_i · w_bsdf |
| `gatherLights`, depth > 0, miss, `escapedRadiance` | per dome/distant light → `L(i)`; plus → `B` | beta · Le_i · w_bsdf; beta |
| `shadeHit`, `cl.emission` | s → `O(objTag)` | beta · Le |
| `shadeHit`, NEE (`evalClosure` + `q.shadows.push`) | per slot k: s → `E(k)` → `L(li)`; parts merged by final state | beta · f_k · mult_k · Li · w_light / pdf |
| `shadeHit`, A events (only if `hasAlbedoOutputs[s]`) | per slot k: s → `E(k)` → `A` | beta · albedo_k |
| `shadeHit`, continuation (`sampleClosure`) | `lpeState[p]` = s → `E(chosen slot)` | (path continues) |
| `traceShadowRays` | parts → outputs if unoccluded; `unoccluded` outputs always (2.7) | part value |

The light-gathering functions in `core/lights/lights.h` (`escapedRadiance`, `cameraEnvironment`, `areaLightsAlongRay`) sum over lights today. They get a template sink, `sink(lightIndex, Le_i)`, which is inlined and costs nothing in the off mode, so each light's share can take its own `L(i)` symbol. Parts are keyed by final state, so a ray crossing many untagged lights still produces one part.

### 2.5 Per-lobe split

**NEE: deterministic and exact.**
- `evalClosure` (`core/bsdf/closure.h`) already loops the non-delta lobes, adding `fcos` and `fcosDiffuse`. M6 adds an optional `Spectrum *fcosBySlot` (template or null pointer): `fcosBySlot[slot[i][side]] += c`, one add per evaluated lobe.
- **Slot assignment.** After `buildSurfaceClosure`, `assignLpeSlots(cl, program, objTag)`, run only in LPE mode, maps each lobe through `lobeClass[side][tag][key]`. Slots are the distinct (class, `Lobe::diffuse`) pairs per side, stored as nibbles in `ClosureList::lpeSlot[kMaxLobes]` (16 B).
  - The diffuse flag is part of the key because the NEE weight applies `light.diffuse` vs `light.specular` per lobe (`shadeHit`: `f = fcosDiffuse * light.diffuse + (fcos - fcosDiffuse) * light.specular`). The Charlie sheen is LPE `D` but not "diffuse" for the multipliers.
  - `kMaxLpeSlots = 6`. Standard Surface needs at most 4 on the reflection side (RD, RD-sheen, RG, RG'coat') and 2 on the transmission side.
  - Overflow, which only generic graphs with many labels could reach, folds into the last slot (biased per component, warned once).
- **Parts.** For each slot with f_k ≠ 0, the final state is `step(step(s, E(k)), L(li))`. Parts with no outputs are dropped, and parts with the same final state are summed. The total stays the existing `contribution`, so the beauty path is unchanged.

**Continuation: stochastic class selection.**
- **The problem.** With more than one lobe, `sampleClosure` returns the mixture weight `f_total(wi)/p_mix(wi)`, whatever lobe was picked. Labelling the path with the *picked* lobe's class gives each component E = ∫ (Σ_{j∈C} p_j pdf_j) f_total/p_mix, not ∫ f_C. That is biased per component, though the sum stays right.
- **The fix.** At the sampled wi the closure already evaluates all lobes (`sampleClosure` → `evalClosure`), and with `fcosBySlot` it has f_k for free. Choose slot k with q_k = lum(f_k)/Σ lum(f_j) and multiply the weight by (f_k/f_total)/q_k, componentwise and safely divided.
  - Per component: E = ∫ p_mix · q_k · (f_total/p_mix) · (f_k/f_total)/q_k = ∫ f_k. **Unbiased.**
  - The beauty is unbiased, and its per-sample luminance weight is unchanged (lum(f_k)/q_k = lum(f_total)); only the hue varies between classes.
  - Delta lobes are outside the mixture and keep their own class. Single-lobe closures and VEX closures (2.6) need no choice.
- **Random number.** It comes from a new stream block, `stream::lpeSplit(depth) = 0x20000 + depth` (`core/math/sobol.h`; the per-bounce slots 0-7 are taken). Other dimensions do not move.
- **Light multipliers.** `diffuseShare` becomes the chosen slot's diffuse flag, which is exact per class instead of a luminance ratio.
- **When it runs.** Only if the closure's lobes fall into more than one slot on the sampled side. With beauty and light groups only, the beauty stays **bit-identical** to LPE-off.

Alternatives considered:

| Option | Per-component bias | Σ == beauty per sample | Beauty changes | Note |
|---|---|---|---|---|
| (a) class of the picked lobe, mixture weight | biased | yes | no | rejected |
| (b) class of the picked lobe, weight f_C / Σ_{k∈C} p_k pdf_k | unbiased | yes | yes | loses the cross-class MIS; weights ~1/pick can spike when the pick estimate under-rates a class |
| **(c) stochastic class by f at wi** | **unbiased** | **yes** | **hue only** | **proposed** |
| (d) as (c), but the reweight goes to a separate LPE throughput | unbiased | only in expectation | no | +12 B per path; comp sums drift from the beauty at low spp |

### 2.6 VEX (external) closures

`ExternalClosure` (`closure.h`, M5 D6/D7) has one `lightF` for the NEE direction and the sampled component's own weight (`sample_bsdf`) for the continuation.
- **Continuation.** The class comes from the bounce bits (`wavefront.cpp:externalClass`); per-component it is already unbiased.
- **NEE.** M6 could evaluate `eval_bsdf` with the bounce masks (diffuse, reflect, refract, sss) in the same bridge run, but only when the program distinguishes them (+1-4 evals per lane). Otherwise the NEE goes to the diffuse class, as `evalClosure` already does for the light multipliers (documented).
- **VEX labels.** Labels on VEX bsdfs (Karma's `coat`) need a bridge query per label. That is deferred unless a probe shows Karma CPU uses them for `mtlx`/`kma` materials too.

### 2.7 Interplay with clamping, RR, limits, NaN, prefixes

- **Clamping** (`clampContribution`, `clampEscape`/`clampNee` in `ShadeContext`). The clamp scale is computed on the *total* contribution of a site and applied to every part, so components still sum to the beauty.
- **Russian roulette** (`shadeHit`, `rrStartDepth`). It scales beta; the parts inherit it. Nothing to do.
- **Ray limits and light-only rays** (`shadeHit`, `eventCounts`/`lightOnly`). The scattering event is appended when it happens, and later light gathering appends `L`. The `maxDepth` cut is unchanged.
- **NaN/Inf.** `renderWave` drops a path whose total is non-finite. With per-output accumulation the check moves to each contribution: `isFinite(c)` before adding it to the beauty and to the outputs. This keeps Σ == beauty.
- **`unoccluded;`** NEE parts with this flag are accumulated whatever `occluded` says.
  - To stay unbiased they use the NEE estimate with MIS weight 1. The shadow entry stores `misWeight` (4 B), and the part value is divided by it.
  - BSDF-sampled light hits do not feed these outputs.
  - Delta lobes, which have no NEE, cannot be unshadowed (documented).
- **`shadow;`** = unoccluded − occluded from the same weight-1 NEE estimate: added only when the ray *was* occluded. Karma's help calls it a "ratio", so a probe must confirm the definition first.
- **`holdout(s);`** is deferred until Nova has holdouts.
- **`!`** is applied when writing: v ← 1 − mean.

### 3.3 AOV buffers, filtering and the beauty

- **Accumulation.** Contributions go straight into `film.lpeSum[out * pixels + pixel]`.
  - A wave owns its tile's pixels, so the CPU needs no atomics.
  - On the GPU (M10) a wave also has one path per pixel. Atomics are needed only if several waves of a tile are in flight.
  - Per-path accumulators would cost outputs × 12 B per path, too much for GPU path counts.
- **Filtering.**
  - Nova uses filter importance sampling (`core/film/filter.h`): every sample has weight 1, and a pixel is the mean of its samples. LPE AOVs are therefore filtered exactly like the beauty, with no weights stored.
  - Karma's per-AOV `driver:parameters:aov:karma:filter` cannot differ from the beauty's filter under FIS. Ignore it, with a note; ids and other utility AOVs are first-hit and unfiltered anyway.
- **Beauty.**
  - The beauty (`colorSum` + `alphaSum`) stays the separately accumulated sum of every `L`/`O` contribution, so it equals `C.*[LO]` by construction (S4).
  - Bindings whose expression normalizes to `C.*`/`C.*[LO]`/`C.*[OL]` keep mapping to it. An exact test would compare the minimized DFA with the beauty's.
  - Any partition of path space then sums to the beauty per sample, e.g. {`C<RD>.*[LO]`, `C<RG>.*[LO]`, `C<TD>.*[LO]`, `C<TG>.*[LO]`, `C[LO]`} (+ `CV.*[LO]` from M8).
  - Karma's presets end in `L`, not `[LO]`, so their sum misses emission seen through bounces. That is by Karma's design.
- **Hydra copy.**
  - `_RenderLoop` calls `WriteFromFilm` for every binding after every pass. With 20 LPE AOVs at 4K that is ~170 M pixel conversions per pass.
  - Copy the beauty (or the AOV the viewport displays: in Solaris only displayed AOVs are bound) every pass, all others when converged, on `Resolve()`/`Map()`, or every N seconds for husk checkpoints.
- **EXR.** husk writes multi-part EXR from the buffers (Karma's LOP sets `driver:parameters:aov:husk:multiSampled` for LPEs; Nova may ignore it). `nova_cli` mirrors the layout (`writeExr`: "C" first, bare channel names for the beauty).

### 3.4 Cost estimate

| Item | Cost | Notes |
|---|---|---|
| Per event | 1 table lookup | `next` + `symbolClass` ≤ 25 KB, L1/L2-resident |
| NEE | 1 indexed add per lobe; per slot 2 lookups, multiplier, part push | typically 1-3 slots |
| Continuation split | luminance of ≤ 6 slots, 1 RNG | only if the closure has more than one slot |
| Film | per contribution, (outputs of the state) × `Spectrum` add | ≤ 6 for Karma's set, 12 with 3 light tags; tile working set 20 × 1024 × 12 B = 240 KB |

- **Time.** About 10-40 ns per bounce against the measured ~700 ns per ray and thread (`cornell_rect`: 21.5-24.3 Mrays/s across M2-M5 on the 16 hardware threads of the Ryzen 9800X3D, `docs/benchmarks.md`), so ~2-5 % CPU with Karma's standard set (~20 AOVs). Below 1 % (and bit-identical beauty) with only beauty or light-group expressions.
- **Memory.**
  - 2 B per path.
  - Shadow parts ≤ 86 KB per thread.
  - Film 12 B per pixel and output: 1080p × 20 ≈ 0.5 GB; 4K × 20 ≈ 2 GB. Plus husk's own render buffers.
- **Benchmark targets for M6:** 0/1/20/74 LPEs on cornell, mtl_spheres and mtl_glass.

### 3.5 Utility (non-LPE) AOVs

Nova today: `renderFirstHitAovs` traces one ray through each pixel center (lens center, frame time) with the first sample and writes `Film::depth/normal/albedo/primId/instanceId`. Those are exact per pixel and unfiltered. Camera-visible lights count as the first hit.

| AOV (Karma source → husk name) | Nova today | M6 proposal |
|---|---|---|
| depth `ray:hitPz` → `depth`; Hydra `depth`/`cameraDepth` | `film.depth`: planar camera depth, 0 = background | Karma's `hitPzfarclip` clear value via `driver:parameters:aov:karma:defaultvalue` |
| P `ray:hitP` → `P`; `ray:hitP_camera` → `P_camera`; Hydra `Peye` | – | `film.position` (world) at first hit; camera space on write |

### 3.6 Tests

1. **Compiler unit tests** (`tests/test_lpe_compile.cpp`):
   - parse errors and messages;
   - every Karma preset;
