# MaterialX node set for Nova M3: semantics, what Karma actually does, and the design

## 0. Key findings

1. **Houdini 22.0.466 ships MaterialX 1.39.5.**
   - Namespace: `MaterialX_v1_39_5`. Version macros are in `$HFS/toolkit/include/MaterialXCore/Generated.h:9-11`.
   - Data libraries: `$HFS/houdini/materialx/libraries/{stdlib,pbrlib,bxdf,cmlib,nprlib,lights,houdini,targets,mdl}`.
   - `stdlib_defs.mtlx` has **693 nodedefs**: **495 primitives** in 106 node categories, plus **198 defined as nodegraphs** in `stdlib_ng.mtlx`.
   - After expanding the nodegraphs, full stdlib coverage needs 495 primitive nodedefs. The nodegraph bodies themselves only use **190 of them, in 51 categories**.
   - With width-generic opcodes this is about 75 VM opcodes.
2. **Karma does not use the MaterialX GLSL or OSL code.** It works in three layers:
   - **(a) VEX code templates per ND_ node, embedded in `$HFS/bin/libBRAY.dll`.**
     - Simple ops start at file offset 0x67d208, e.g. `ND_add_float` → `$out = $in1 + $in2;`.
     - Complex ops start at 0x68f660, e.g. `ND_noise2d_float` → `float out_$NODE_ID = mxstd_noise($amplitude, $pivot, $texcoord);`.
     - Every one of the 495 stdlib primitives has a template.
   - **(b) The VEX library `$HFS/houdini/vex/include/mxstd.h`** (1897 lines), plus `mxpbr.h`, `mxtypes.h` and `kvex_mtlx.h`.
   - **(c) The noise built-ins `mx_perlin`, `mx_cellnoise` and `mx_worley`, compiled into `libVEX.dll`.**
   - **Nodegraphs are not expanded at run time.** Karma loads a pre-expanded `$HFS/houdini/karmaNodeGraphs.json` (287 defs), generated by `$HFS/houdini/python3.13libs/mtlx2karma.py`.
     - Every graph in it has exactly the same node count as `stdlib_ng.mtlx`, so it was generated from the same library.
     - The only stdlib nodedefs Karma does not know are `ND_smoothstep_vector2/3/4`.
3. **Noise matches the MaterialX reference bit for bit, verified.**
   - I ported `mx_noise.glsl` to C++ (§6.1) and compared it with Houdini's `mx_perlin`, `mx_cellnoise` and `mx_worley` through `vexexec -A 32` on 2000 points.
   - Perlin (float and vector, 2D and 3D) max abs difference: **6e-8** (1 ulp).
   - fBm: 1.2e-7.
   - Cell noise and Worley (F1, F2, F3, Euclidean and Manhattan): **exactly 0**.
   - The Karma render probe (§4) confirms the same for noise2d/noise3d/fractal3d/cellnoise/worley, including Worley's "solid" style and the default noise3d position being object space.
4. **Karma differs from MaterialX 1.39.5 in several places. All were verified with husk renders** (`husk --renderer BRAY_HdKarma`, unlit quads, §4):
   - `ramptb` and `splittb` are upside down: Karma gives `valuet` at v=0. MaterialX flipped these in **1.39.5**; 1.39.0 through 1.39.4 behave like Karma.
   - `ramplr` and `ramptb` do not clamp the texture coordinate in Karma.
   - `smoothstep` with low ≥ high: Karma computes `clamp((t-lo)/(hi-lo))` with safe division, so `low == high` gives **0 everywhere**.
   - `dodge` is `1 - bg/(1-fg)` in Karma (`mxstd.h:1037`), which does not match the spec.
   - Address mode `constant` returns **black, not `default`**.
   - VEX "safe math" applies to every node: x/0 = 0, sqrt(−x) = 0, log(≤0) = 0, normalize(0) = 0, and integer-rounded `pow` for negative bases.
   - `heighttonormal` is a world-space bump in Karma, not MaterialX's screen-space Sobel/16.
5. **Color space metadata reaches Karma.** In USD 26.05, Hydra passes `colorSpace:<input>` parameters, and Karma honours them.
   - Verified: an 8-bit sRGB PNG with `colorSpace = "lin_rec709"` on `inputs:file` is read raw.
   - The Houdini docs saying "Hydra doesn't pass metadata" are out of date.
   - Without metadata: color3/color4 image nodes use `'auto'` (OCIO file rules); float and vectorN signatures are raw.
6. **Recommended expansion strategy: do it at run time with Houdini's MaterialX C++ API, but don't use `HdMtlxCreateMtlxDocumentFromHdNetwork`.**
   - That function deep-copies the library into every document (`importLibrary`). Measured cost: **18 ms per material**.
   - Instead build the `mx::Document` yourself with `setDataLibrary(sharedLib)`, then call `flattenSubgraphs(filter)` (**0.18 ms**).
   - `flattenSubgraphs` inserts `geomNode_UV0`-style nodes for nodegraph interface inputs that have a `defaultgeomprop`, so tiledimage, checkerboard etc. come out correct.

## 3. How Karma evaluates a MaterialX network

1. The Hydra network gives ND_ ids.
2. Graph nodes are expanded from `karmaNodeGraphs.json`.
3. Each primitive's template is instantiated as VEX source:
   - `out_$NODE_ID` names the result; `$input` stands for an input value or the upstream variable.
   - The shader includes `<mxtypes.h>`, `<mxstd.h>`, `<mxpbr.h>` and `<kvex_mtlx.h>`.
4. The result is compiled as one VEX surface shader. The preamble computes `computedTanU/V` with `mxstd_computeTangents(isbound('st'), normalize(N), st, __prim_tanu, __prim_tanv, …)`.

KVEX (`vexexec -k`) is a restricted subset (no `normalize`, no `mx_perlin`), so the MaterialX templates are compiled as ordinary VEX.

**VEX arithmetic semantics apply to every node.** Verified with `vexexec -A 32`, run-time (non-folded) values:

| Expression | VEX/Karma result | GLSL/OSL (MaterialX ref) |
|---|---|---|
| `x/0`, vector/0 | 0 | ±inf / NaN |
| `x % 0` | 0 | NaN |
| `-0.25 % 1`, `2.5 % -1` | 0.75, −0.5 (floored, same as GLSL `mod`) | same |
| `sqrt(-2)`, `log(0)`, `log(-2)` | 0, 0, 0 | NaN, −inf, NaN |
| `asin(-2)`, `acos(-2)` | −π/2, π (clamped input) | NaN |
| `pow(b<0, e)` | `b^rint(e)`: pow(−2, 0.5) = −2, pow(−2, 1.5) = 4, pow(−2, 0.3) = 1, pow(−3, 2.5) = −27 | NaN |
| `pow(0, -0.5)` | 0 | inf |
| `rint` (= ND_round) | floor(x + 0.5): 0.5→1, 2.5→3, −0.5→0, −1.5→−1 | GLSL `round` is implementation-defined; OSL rounds half away from zero |
| `normalize(0)` | 0 vector | NaN |
| `clamp(0.5, lo=1, hi=0)` | 1, i.e. `max(lo, min(x, hi))` | undefined |
| `efit(x, a, a, …)` | (outlow + outhigh)/2 (observed 0.5) | division by 0 |
| `exp(100)` | inf (no clamp) | inf |

**Do not reuse `nova::normalize` from `core/math/vec.h` for shading ops.** It returns (0,0,1) for a zero vector.

### 4.1 Noise: exact algorithm (OSL-derived, `mx_noise.glsl`; identical in Karma)

**Hash (Bob Jenkins lookup3):**
- `mx_bjmix` (lines 136-146) and `mx_bjfinal` (147-157).
- Seed: `0xdeadbeef + (len<<2) + 13`.
- `hash(x,y) = bjfinal(seed + x, seed + y, seed)`.
- For 4 arguments: `bjmix(a, b, c)` after x, y, z, then `a += w`.
- `bits_to_01(b) = float(b) / float(0xffffffff)`; the denominator is 4294967296.0f in float32.

**Perlin:**
- `mx_floorfrac` with `int(floor(x))`.
- Quintic fade: `t³(t(6t − 15) + 10)`.
- 2D gradient (line 95): `h = hash & 7`; u = h<4 ? x : y; v = 2·(h<4 ? y : x); negate u if bit 1, negate v if bit 2.
- 3D gradient: `h & 15`, edge-of-cube vectors.
- Scale: **0.6616 (2D)** and **0.9820 (3D)**.
- Vector Perlin uses the bytes `(h >> 0, 8, 16) & 0xFF` of the corner hash, so channel x equals the float noise.

**noise2d/3d:** `value * amplitude + pivot`.
- vector2 output = xy of the vector noise.
- vector4 output = (xyz noise, float noise at p + (19, 73) in 2D or p + (19, 73, 29) in 3D).
- Karma: `mxstd_noise`, `mxstd.h:814-863`, same offsets.

**fractal2d/3d:** `Σ_{i<octaves} diminish^i · perlin(p · lacunarity^i)`, with p scaled incrementally, then × amplitude.
- vector2 output = (f(p), f(p + (19, 193)) in 2D or f(p + (19, 193, 17)) in 3D).
- vector4 output = (vec3 fBm, float fBm at the same offset).
- Karma: `mxstd_fractal_noise`, `mxstd.h:708-812`.

**cellnoise2d/3d:** `bits_to_01(hash(floor(x), floor(y)[, floor(z)]))`.

**Worley** (2D: 3×3 cells, 3D: 3×3×3):
- Feature point = `cell + 0.5 + (cellnoise_vec3(cell) − 0.5)·jitter`.
- `cellnoise_vec3(vec2) = (hash(ix, iy, 0..2))`.
- `cellnoise_vec3(vec3)`: seed(4), `bjmix(a,b,c)` on ix/iy/iz, then `bjfinal(a+k, b, c)` for k = 0..2.
- Distance metric 0 (Euclidean, sqrt applied at the end), 1 (squared), 2 (Manhattan), 3 (Chebyshev). The nodes always use metric 0.
- Keeps F1 ≤ F2 ≤ F3. Style 1 (solid) = `cellnoise(minpos + p)`, float or vec3.
- Karma: `mx_bray_worley($texcoord, $jitter, $style, 0)`.

The OSL target (`genosl`) uses OSL's built-in `noise("snoise")`/`cellnoise`, which the GLSL file states produce identical results.

### 4.2 Ramps and splits

| Node | MaterialX 1.39.5 (genglsl/genosl) | Karma (libBRAY template) |
|---|---|---|
| ramplr | `mix(l, r, clamp(u, 0, 1))` | `lerp(valuel, valuer, texcoord.x)` |
| ramptb | `mix(valueb, valuet, clamp(v, 0, 1))` (spec: valuet at V = 1) | `lerp(valuet, valueb, texcoord.y)` |
| splitlr | `mix(l, r, aastep(center, u))` | `lerp(valuel, valuer, filterstep(center, texcoord.x))` |
| splittb | `mix(valueb, valuet, aastep(center, v))` | `lerp(valuet, valueb, filterstep(center, texcoord.y))` |
| ramp4 (graph) | clamps uv, top row at v = 1 | same graph, so consistent with MaterialX |

`aastep` and `filterstep` are derivative-filtered steps. In a path tracer use a hard step; pixel supersampling converges to the same average.

### 4.3 image / tiledimage

**Nodedef** (`stdlib_defs.mtlx:139`):
- Inputs: `file`, `layer`, `default` (= 0), `texcoord` (defaultgeomprop **UV0**), `uaddressmode`/`vaddressmode` (constant | clamp | **periodic**), `filtertype` (closest | **linear** | cubic), `framerange`, `frameoffset`, `frameendaction`.

**MaterialX reference (genosl, which uses OIIO):**
- `file == ""` → `default`.
- Mode constant with u or v outside [0,1] → `default`.
- Otherwise `texture(file, u, 1 - v, "swrap", umode, "twrap", vmode, "interp", filtertype, "missingcolor", default)`. The v-flip is because OIIO's (0,0) is the top-left (`lib/mx_transform_uv_vflip.osl`).
- genglsl relies on sampler state plus `uv_scale/uv_offset`, which is how UDIM sets are handled there.

**Karma** (`mxstd.h:479-554`, `mxstd_image_vector3`):
- UDIM: `udim = has_udim(file)`, then `expand_udim(u, v, file)`. Tokens `<UDIM>`, `%(UDIM)d`, `<UVTILE>`, `%(U)d`, `%(V)d`, with tile = `1000 + int(u)+1 + int(v)*10`. Note `int()` truncates; the spec uses the integer part, i.e. floor for positive uv.
- A missing tile returns `default`.
- With UDIM, address modes are ignored: in-tile coordinates are `clamp((u % 1) ± dd, 0, 1)` (`_mxstd_textureWarp`, `mxstd.h:418`).
- Modes: constant/"black" → VEX `decal` (observed result: black), clamp, periodic, mirror (manual).
- Filter mapping (`_mxstd_vexFilter`/`_vexFilterMode`, `mxstd.h:349-377`): closest → `"point"`; others → `"box"`; cubic → filtermode `"bicubic"`, otherwise `"filter"` (mip-mapped area filtering).
- Footprint: `width = mtlx_imagewidth·karma_width`, `blur = mtlx_imageblur + karma_blur`.
- `framerange/frameoffset/frameendaction`: **ignored** (`// TODO: Frame range expansion`, `mxstd.h:333`). The docs also say MaterialX frame tokens are not supported.
- Color space: `srccolorspace = karma_srccolorspace or ('auto' for color3/4, 'raw' for float/vector2/3/4)`. Ignore the `// TODO: colorspace … stopgap` comment: USD `colorSpace` metadata is honoured anyway (probe).
- The MaterialX spec defines filename tokens `<UDIM>` (1001 + U + 10V) and `<UVTILE>` (`u{U+1}_v{V+1}`) (`MaterialX.Specification.md:564-565`). USD's `UsdUVTexture` only knows `<UDIM>`.
- **tiledimage** is a graph: `image(texcoord·uvtiling − uvoffset) / realworldimagesize · realworldtilesize`, with periodic modes. Karma docs: "UDIMs do not work with MtlX Tiled Image".

**cmlib transforms** (graphs; target lin_rec709):
- `srgb_texture`: `c ≤ 0.04045 ? c/12.92 : pow(max(c + 0.055, 0)/1.055, 2.4)`. The threshold test is `ifgreater(c, 0.04045)`.
- `g18_rec709`, `g22_rec709`, `rec709_display`: `pow(max(c, 0), 1.8 / 2.2 / 2.4)`.
- `acescg → lin_rec709`: `out = in * M` (row vector) with M = [[1.705051, −0.130256, −0.024003], [−0.621792, 1.140805, −0.128969], [−0.083259, −0.010548, 1.152972]].
- `lin_displayp3`: matrix in `cmlib_ng.mtlx`.
- In Nova, resolve names through Houdini's OCIO config first, as `hydra/textureCache.cpp` already does. Use the cmlib formulas only as a fallback for MaterialX names the config lacks.
- **A neutral-gray test cannot detect a primaries mismatch** between lin_rec709 and an ACEScg scene_linear. Use a saturated color.

### 4.4 Geometric nodes and spaces

- **texcoord:** Karma uses `isbound('st') ? st : set(s,t)`. `index` is ignored, and so is any other UV set name. MaterialX UV0 → USD primvar `st`.
- **position / normal / tangent / bitangent:** default `space="object"`, enum model | object | world (`stdlib_defs.mtlx:1463-1490`).
  - Karma: `mx_ptransform('space:current', $space, P, …)`; `normalize(mx_ntransform($space, N, …))`; `normalize(mx_vtransform($space, computedTanU / computedTanV, …))`.
  - `_mx_space` (`mxstd.h:41`) maps object and model → `space:object`, world → `space:world`, plus camera/ndc/screen/raster/tangent.
  - Object space of an instance is the **prototype's local space** (verified for PointInstancer).
- **Tangent frame** (`mxstd_computeTangents`, `mxstd.h:1150`), when `st` is bound:
  - `T = normalize(dPdu − N(N·dPdu))`, `B = normalize(N × T) · sign(dot(T × dPdv, N))`, where dPdu and dPdv come from the st parametrization.
  - Degenerate case: `makebasis`.
  - These are Karma's `Tworld` and `Bworld`, used as defaults by normalmap, bump and standard_surface.
- **geompropvalue:** `isbound('$geomprop') ? TYPE($geomprop) : $default`. Interpolation is auto-detected; only uniform strings work for the name.
- **geomcolor:** `isbound("displayColor") ? displayColor : {1,1,1}`.
- **frame:** `renderstate('renderer:frame', 1)`.
- **time:** `(frame − 1) / renderer:fps` (default 24). MaterialX GLSL uses frame/fps, so they differ by one frame.

### 4.5 normalmap, heighttonormal, bump

**MaterialX 1.39.5** (`genglsl/mx_normalmap.glsl`):
```
v = dot(in,in)==0 ? (0,0,1) : in*2-1
out = normalize(T*v.x*s.x + B*v.y*s.y + N*v.z)
```
T and B are used unmodified; defaults are Nworld, Tworld, Bworld.

**Karma** (`ND_normalmap_vector2`/`float` → `mxstd_normalmap(in, scale, N, T, B, !karma_mikkt)`, `mxstd.h:1102-1148`). With the default `karma_mikkt = 0`:
- Gram-Schmidt: `T' = norm(T − N(N·T))`, `B' = norm(B − N(N·B))`.
- `r = norm(T'·v.x·s.x + B'·v.y·s.y + N·v.z)`.
- If `sign(r·Ng) ≠ sign(N·Ng)`, then `r −= Ng·(r·Ng)·1.001` (no renormalisation).
- No zero-input special case.

**heighttonormal:**
- MaterialX: screen-space `dFdx/dFdy` of height × scale/16 (Sobel parity), built into a tangent frame, encoded ×0.5 + 0.5.
- **Karma: a world-space bump** (`mxstd.h:1065`): `P' = P + ng·in·scale`; `wn = computenormal(P')`; expressed in the frame `(norm(tu⊥ng), norm(tv⊥ng), ng)` via `invert(frame)`; normalized; ×0.5 + 0.5. The `texcoord` input is ignored.
- The magnitudes are completely different between the two. Follow Karma.
- **bump** = graph heighttonormal → normalmap (2 primitives).

### 4.6 Other details worth copying exactly

| Node | Formula |
|---|---|
| smoothstep | MaterialX: `t ≥ hi → 1; t ≤ lo → 0; else smoothstep`. Karma (`mxstd.h:95`): `x = clamp((t − lo)/(hi − lo), 0, 1); x²(3 − 2x)` with VEX division. Color/vector variants are graphs (per component). `ND_smoothstep_vector2/3/4` are unknown to Karma. |
| luminance | `dot(in, lumacoeffs)`, default acescg (0.2722287, 0.6740818, 0.0536895). color4 keeps alpha. |

## 5. Design recommendation for Nova

### 5.1 Host pipeline (`hydra/material/`, the only place that touches MaterialX/USD)

1. **`HdNovaMaterial : HdMaterial`** (new Sprim `HdPrimTypeTokens->material`).
   - `Sync`: call `GetMaterialResource`, then `HdConvertToHdMaterialNetwork2`.
   - Terminals: `surface` (also `displacement` and `volume` later).
   - Hash the network (node types, params, connections) and dedupe identical programs.
2. **`MtlxLibrary`** (singleton, loaded once):
   - `mx::loadLibraries({"libraries"}, searchPath, lib)`.
   - Search path from env `PXR_MTLX_STDLIB_SEARCH_PATHS` (set by HUSD in husk/Houdini), otherwise `$HFS/houdini/materialx`, plus `PXR_MTLX_PLUGIN_SEARCH_PATHS` for user libraries.
   - Measured: 72 files, 898 nodedefs, 282 nodegraphs in **41 ms**. The library includes `houdini/` (hmtlx* graphs, legacy defs).
3. **Build the document without copying the library:**
   ```cpp
   mx::DocumentPtr doc = mx::createDocument();
   doc->setDataLibrary(lib);               // 0 copies; importLibrary costs 18 ms per material (hdMtlx does that)
   mx::NodeGraphPtr g = doc->addNodeGraph("NG_mat");
   for (auto &[path, hn] : net.nodes) {     // only nodes reachable from the terminal
       mx::NodeDefPtr nd = lib->getNodeDef(HdMtlxGetNodeDefName(hn.nodeTypeId.GetString())); // ND_normalmap -> ND_normalmap_float
       if (!nd) { warnOnce(hn.nodeTypeId); continue; }               // M5: CvexNode
       mx::NodePtr n = g->addNode(nd->getNodeString(), mangle(path), nd->getType());
       n->setNodeDefString(nd->getName());
       for (auto &[name, val] : hn.parameters) {
           const std::string s = name.GetString();
           if (TfStringStartsWith(s, "colorSpace:")) { colorSpace[{path, s.substr(11)}] = val; continue; }
           if (TfStringStartsWith(s, "typeName:")) continue;
           mx::InputPtr def = nd->getActiveInput(s);
           if (!def) continue;                                       // karma_* extras etc.
           mx::InputPtr in = n->setInputValue(s, HdMtlxConvertToString(val), def->getType());
           // colorspace -> in->setColorSpace(...)
       }
   }
   // connections: in = n->addInputFromNodeDef(name); in->setConnectedNode(up);
   //   multi-output upstream: in->setOutputString(conn.upstreamOutputName)
   g->flattenSubgraphs(mx::EMPTY_STRING, [](mx::NodePtr n) {
       return !isNativeNodeDef(n->getNodeDefString());   // false keeps it: standard_surface, open_pbr_surface, kma_* ...
   });
   ```
   Verified on 1.39.5 (scratch `cpp/flatten.cpp`): `flattenSubgraphs` resolves interface values to nodedef defaults and **inserts `geomNode_UV0` texcoord nodes** for nodegraph interface inputs with a `defaultgeomprop`.
   Two things it does not do:
   - Unconnected inputs of *primitive* nodes (noise3d `position` = Pobject, image `texcoord` = UV0, normalmap `normal/tangent/bitangent` = Nworld/Tworld/Bworld) stay unconnected. The lowering must read `nodeDefInput->getDefaultGeomProp()` and emit a geometry op.
   - Don't call `doc->validate()` with Houdini's libraries attached. It reports "too many bindings" errors from the shipped library graphs.
   hdMtlx assumes document version 1.38 when no `config:mtlx:version` is authored, then runs `upgradeVersion()`. The 1.38→1.39 renames (atan2 `in1/in2` → `iny/inx`, swizzle → extract/combine, normalmap space) are keyed by input name, so they are safe on 1.39 data. Apply `upgradeVersion()` the same way.
4. **Lower `g->topologicalSort()` to IR** using a table keyed by node category plus type:
   - Width 1..4 from the type.
   - FA variants: splat the scalar operand.
   - `dot`, `constant` and `convert(boolean/integer)` disappear.
   - `invert` → `Sub(amount, in)`; `inside` → `Mul`; `outside` → `Mul(in, 1 − mask)`.
   - `extract`/`combineN` → swizzle/gather.
   - `ifgreater` family → `CmpGt` + `Select`.
   - Uniform strings (address modes, spaces, geomprop names, file) → immediates or slot tables.
5. **Optimize the IR.** This is essential: ND_ramp expands to 270 primitives, tiledhexagons to 159, randomcolor to 75, triplanarprojection to 60.
   - **Constant folding by running the core kernels** on 1-lane constant batches, so folding is bit-identical to run time.
   - Select with a constant condition → take the branch (collapses switch/ifgreater chains).
   - Algebraic identities: ×1, +0, mix 0/1.
   - CSE (e.g. repeated `texcoord`/`position` reads); DCE from the closure terminal.
6. **Register allocation** (linear scan over SSA live ranges; vecN = N consecutive scalar slots), then **emit bytecode** plus a constant pool, image-slot table, primvar-slot table and a `needs` bitmask (st, tangents, Pobj, derivatives, …).
7. Call `scene->updateMaterial(materialId, ShaderProgramDesc)` with a POD argument.
   - Meshes get a `materialId`, per triangle when there are GeomSubsets, and a primvar table.
   - `commit()` packs all programs into one flat `ProgramTable` and resolves (program primvar slot → mesh primvar index) per (mesh, material) pair.

**Why run time and not an offline table like Karma:**
- hdNova already links USD/MaterialX.
- User nodegraph libraries work with no extra step; Karma needs `mtlx2karma.py` for those.
- Version upgrades and `HdMtlxGetNodeDefName` come for free.
- If the GPU build ever needs a MaterialX-free path, the same flattener can dump a `karmaNodeGraphs.json`-style table.

### 5.2 `core/shading/`: POD bytecode, GPU-portable

```cpp

    Op op; uint8_t width; uint8_t flags;   // flags: compat (karma|spec) bits, broadcast bits
    uint16_t dst; uint16_t src[3];         // bit15 set = constant-pool index (uniform), else per-lane register
    uint32_t imm;                          // slot / mode / index into args[] for ops with >3 operands
};

```

**Interpreter, CPU side.** Run per material over sorted lane chunks of `kShadeBatch = 256`, with registers as `float regs[regCount][256]`. Each operand resolves to `{const float* p; uint32_t laneStride /*1 = register, 0 = constant*/}`. The inner loop is a branch-free `for lane in [0, n)` that vectorizes with stride 1. Memory: 64 regs × 256 × 4 B = 64 KB per thread.

**GPU (M10).** Same `Instr` stream: one thread per lane, `float regs[kMaxRegs]`, constants in constant memory.

**Control flow.** There is none. MaterialX conditionals are value selects, so lanes never diverge inside a program; sorting by material handles divergence between programs.

**Wavefront integration** (`core/integrator/wavefront.cpp`): split today's `shadeSurfaces` into stages.
1. `resolveHits`: SoA ShadingPoint with P, **Pobj** (barycentric interpolation of the object-space vertices before the instance transform, which is exact under deformation blur), N, Ng, st, dPdu/dPdv from the triangle's st, mesh/prim/bary, matId and wo.
2. Counting sort by matId.
3. `evaluateMaterials`: VM → `ClosureParams` SoA (the standard_surface/OpenPBR parameter block) plus the shading normal.
4. The existing NEE and BSDF-sampling code builds a POD uber-BSDF from `ClosureParams`. The albedo AOV comes from the closure's base color.

**Derivatives** (image footprint, heighttonormal, bump). Use "shifted re-evaluation" like Cycles' bump:
- The compiler duplicates the upstream subgraph of a texcoord or height input twice, with globals offset by (dPdx, duvdx) and (dPdy, duvdy) from ray differentials or ray cones.
- The image op takes the uv Jacobian from the three evaluations.
- heighttonormal uses Karma's world-space bump on the finite differences.
- This avoids dual-number variants of every opcode.

**Compatibility switch.** Add `nova:mtlxSemantics = "karma"` (default; Karma is the plan's reference) or `"spec"` (MaterialX 1.39.5). Encode it per instruction in `flags`. Only the ops in the divergence table below change: Div/Mod/Sqrt/Ln/Pow/Asin/Acos/Normalize/Round/Clamp, Smoothstep, RampLR/TB, SplitTB, Blend dodge/burn, Image constant-mode default, NormalMap, HeightToNormal.

### 5.3 Scene data M3 must add

- `MeshDesc::primvars`: name hash, type width, interpolation, data. Expand faceVarying to triangle corners, keep vertex per point and uniform per triangle.

```cpp
    float r = 1.0f / det; dPdu = (e1 * dv2 - e2 * dv1) * r; dPdv = (e2 * du1 - e1 * du2) * r; }
NOVA_INLINE void karmaTB(Vec3f N, Vec3f dPdu, Vec3f dPdv, Vec3f &T, Vec3f &B) {
    T = vNormalize(dPdu - N * dot(dPdu, N));                    // if T == 0: arbitrary basis (VEX makebasis)
    float s = dot(cross(T, dPdv), N); B = vNormalize(cross(N, T)) * (s > 0 ? 1.0f : (s < 0 ? -1.0f : 0.0f)); }
NOVA_INLINE Vec3f normalMapKarma(Vec3f in, Vec2f sc, Vec3f N, Vec3f T, Vec3f B, Vec3f Ng) {
    Vec3f v = in * 2.0f - Vec3f{1, 1, 1}, n = vNormalize(N), ng = vNormalize(Ng);
    Vec3f t = vNormalize(T - n * dot(T, n)), b = vNormalize(B - n * dot(B, n));
    Vec3f r = vNormalize(t * (v.x * sc.x) + b * (v.y * sc.y) + n * v.z);
    float rd = dot(r, ng), nd = dot(n, ng);
    auto sgn = [](float x) { return x > 0 ? 1 : (x < 0 ? -1 : 0); };
    return sgn(rd) == sgn(nd) ? r : r - ng * (rd * 1.001f); }
// Image coordinates (Karma): UDIM tile = 1001 + floor(u) + 10*floor(v) (VEX uses int()); in-tile s = vMod(u,1), t = vMod(v,1), wrap clamp;
// missing tile -> default. Non-UDIM: wrap per address mode; 'constant' -> 0 (Karma) | default (spec).
// OIIO lookup: (s, 1 - t); wrap modes are symmetric under the flip.
```

## 8. Pitfalls

- **Divergences (decide via `nova:mtlxSemantics`, default `karma`):** see the table in §4. MaterialX itself changed ramptb/splittb in 1.39.5; 1.39.0–1.39.4 match Karma.
- `HdMtlxCreateMtlxDocumentFromHdNetwork` costs 18 ms per material (library deep copy). Use `setDataLibrary`.
- Hydra syncs Sprims in parallel. Use one `mx::Document` per material over a shared read-only data library, and never mutate the library.
- `flattenSubgraphs` leaves `defaultgeomprop` inputs of primitive nodes unconnected; the lowering must supply them (UV0, Pobject, Nworld, Tworld, Bworld).
- Karma reads texture coordinates only from primvar `st` and ignores `index`.
- The default space of position/normal/tangent nodes is **object**, not world. Object space of an instance is the prototype space.
- OIIO's t axis points down: look up `(s, 1 - t)`. Resolve UDIM tiles before flipping.
- OIIO wrap mode "black" reproduces Karma's `constant`; the spec's `default` needs the explicit range test, as in genosl.
- Image frame tokens and `framerange` are ignored by Karma. Warn if they are set.
- Large graph expansions: constant folding and DCE are mandatory, and the register file grows with graph width.
- Floating point: use `floorf` (OSL's `quick_floor` differs at exact negative integers), and compute `bitsTo01` as `float(bits)/4294967296.0f`.
- VEX `rint` rounds half up; `clamp` with lo > hi returns lo.
- `ND_smoothstep_vector2/3/4` do not exist in Karma (unknown node). Nova handles them through the graph.
- The Houdini docs say compositing nodes are "not supported by Karma", but templates exist (and dodge differs).
- A neutral-gray color-space test cannot reveal a primaries error.
