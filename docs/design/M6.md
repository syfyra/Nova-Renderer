# M6 design: AOVs, light path expressions and cryptomatte

Status: binding design for M6. docs/PLAN.md asks for "AOVs: LPE (OSL-LPE-Syntax),
Beauty-Komponenten, Utility (P, N, Z, albedo, crypto-matte), Multi-Part EXR via husk", with the
result "Comp-fertige Ausgabe".

Research, measured on this machine (Houdini 22.0.466, isolated hython/husk only):
- `docs/research/m6/karma-aovs.md`: what Karma's LOPs author, Karma's LPE dialect, and what husk hands a delegate;
- `docs/research/m6/cryptomatte.md`: Karma's cryptomatte, the hash, and the husk route for extra planes and metadata (verified with a probe delegate);
- `docs/research/m6/lpe-design.md`: the LPE grammar, the automaton, and the integration into Nova's wavefront integrator.

Probe scripts are in `docs/research/m6/probes/`.

## 1. Decisions

As in M4 and M5, the user is not available during this /goal run. The recommended options were taken; the user may revise them.

| # | Question | Decision |
|---|---|---|
| D1 | AOV vocabulary | **Karma's.** Nova renders the RenderVars Karma's LOPs author (Karma Render Settings, Karma Standard Render Vars, Cryptomatte, `kma_aov`): LPE, `raw` (`ray:*`, shader AOVs) and `primvar` sources, under their `husk:name`. Hydra's standard names (`color`, `depth`, `normal`, `primId`, `instanceId`, `albedo`, `Peye`, `elementId`) keep working. Unknown sources stay at their clear value, with one warning per AOV. |
| D2 | LPE dialect | OSL's grammar with Karma's changes: `S`/`s` are parsed but match nothing (Karma makes every specular event `G`); terminators `A` (albedo) and `B` (background); prefixes `unoccluded;`, `shadow;`, `holdout;`; `!` before the whole expression; positional custom labels `<event scatter 'tag' 'label'>`. `holdout;` renders black with a warning until Nova has holdouts. Parse errors warn once per AOV; the AOV stays clear. |
| D3 | Runtime representation | **One minimized product DFA** for all bound LPEs, built per AOV-binding change on the host: Thompson NFA, subset construction over whole events, Moore minimization, alphabet compression. Each path carries one `uint16_t` state. An event is one lookup `next[state * classes + symbolClass[symbol]]`. Final states list their output ids. If the DFA would exceed 65 535 states or 1 MB, the outputs are split into groups with one state each. |
| D4 | Events | Karma's measured semantics (karma-aovs.md 2, lpe-design.md 1.4): `D`/`G` from the lobe; `R`/`T` from the side of the geometric normal; SSS and translucency `<TD>` on either side; delta lobes `G`. Labels: native coats `'coat'`, SSS `'sss'` (sheen unlabelled, as measured in Karma in M6.3). Tags: lights `inputs:karma:light:lpetag`; objects the constant primvar `karma:object:lpetag`, else the material's `inputs:karma:lpetag`. Stochastic opacity, fake-caustic pass-throughs and light-only crossings append no event. `.` and `[^...]` never match `A`/`B` at the type position, so `C.*` ≡ `C.*[LO]`. |
| D5 | Splitting a closure between components | NEE: **deterministic and exact.** `evalClosure` also returns the parts per slot; a slot is a distinct (symbol class, light-multiplier kind) pair, at most 6 per closure. Continuation: **stochastic class selection.** Pick slot k with probability lum(f_k)/lum(f) at the sampled direction and weigh it by (f_k/f)/q_k. This is unbiased per component and keeps the cross-lobe MIS; the sum of the components equals the beauty per sample. With only the beauty or light groups there is one class and nothing changes (bit-identical beauty). |
| D6 | Accumulation | Per output, a film sum per pixel (12 B); tiles are thread-exclusive, so no atomics. Filter importance sampling means every LPE AOV is filtered exactly like the beauty. Clamping scales every part by the factor of the site's total. The NaN check moves to each contribution, beauty included. The beauty keeps its own sum; bindings whose DFA equals the beauty's map to it. |
| D7 | `unoccluded;` and `shadow;` | `unoccluded;X` accumulates X's NEE parts whether the shadow ray is blocked or not, with MIS weight 1 (BSDF-sampled light hits do not feed it). `shadow;X` is Karma's measured **occluded fraction**: per pixel 1 − (X lit with weight-1 NEE) / (X unoccluded), computed when the buffer is written from two sums. |
| D8 | `A` and `B` | `A`: throughput × the albedo of the lobes of the event's class at wo (`CDA` = the first hit's diffuse albedo; `C<TG>*DA` looks through glass). `B`: throughput × 1 on escape (an alpha quantity: `!C<TG>*B` = alpha through glass). Domes and distant lights stay `L` events with their radiance. |
| D9 | Utility AOVs | **First hit at the pixel centre, unfiltered** (Nova's M2 decision; Arnold's "closest" convention), for `ray:hitP`, `ray:hitP_camera`, `ray:hitPz` (depth), `ray:hitN`, `ray:hitNg` (+ `_camera`, `_facing`, `_facingratio`), `ray:element`, `ray:primid`, `ray:hitdist`, `ray:motionvector`, `ray:velocity`, primvar sources (`st`, any primvar), shader AOVs (`raw` names a material output: `kma_aov`'s `inputs:aov:<name>`, VEX `export_*` parameters) and `AO`. Ids honour `husk:format float` (husk copies the buffer's bytes, so a float file needs float values). Karma filters P/N with ubox and ids with idcover; edges differ (documented). |
| D10 | Cryptomatte | As Karma, through husk's extra-AOV route: `HdRenderBuffer::GetResource()` returns `extra_aov_resource` → `UT_HUSDExtraAOVResource` (header-only, Apache-2.0) with ⌈rank/2⌉ planes `<name>NN` (id, coverage, id, coverage) and the metadata `cryptomatte/<7 hex>/name, hash, conversion, manifest` (or `manif_file` for a sidecar, which husk writes). Names: the gprim's scene path (`HdPrimOriginSchema`; native instances: the first `instanceLocations` entry + the relative path), the bound material path (`defaultshader` unbound), or a primvar (ints as decimal strings). Hash: MurmurHash3_x86_32, seed 0, exponent fixup. Coverage: per camera sample the first visible id (after stochastic opacity) gets weight 1, divided by the pixel's sample count; a small id/weight table per pixel; sorted descending, cut at the rank. The RenderVar's own float3 buffer gets the preview colour. `nova_cli` writes the same parts and header keys. |
| D11 | Hydra fixes found by the research | The clear value arrives as a scalar float even for vector buffers: broadcast it to every channel. AOVs Nova cannot fill are cleared, never left with stale or uninitialized data. Non-displayed AOVs are copied from the film when the render converges or a buffer is mapped, not after every pass. |
| D12 | Solaris UI | Karma's render-var LOPs (Karma Render Settings' AOV toggles, Karma Standard Render Vars, Karma Cryptomatte, LPE Tag) are the AOV UI for Nova too. The Nova Render Settings LOP gets the same AOV toggles, authoring Karma-identical RenderVars (with `husk:format`), so a Nova setup also renders in Karma. |

## 2. Scope

### 2.1 M6 delivers

- Every LPE RenderVar Karma's LOPs author (beauty, the diffuse/glossy/transmission/coat/SSS/emission/visible-lights families with direct/indirect and unoccluded/shadow variants, light-tag splits, the albedo family, `!C<TG>*B`), and any user LPE in the dialect of D2.
- The utility AOVs of D9 under Karma's and Hydra's names.
- Shader AOVs: `kma_aov` (material `outputs:<name>` / shader `inputs:aov:<name>`) and VEX `export_*` parameters of bridge materials.
- Cryptomatte for prims, materials and primvars, with manifest or sidecar.
- The first-hit albedo of VEX materials (black since M5).
- Multi-part EXR through husk (husk writes the files) and through `nova_cli` (the same layout).
- The Nova Render Settings LOP's AOV toggles.

### 2.2 Deferred

| Item | Goes to | M6 behaviour |
|---|---|---|
| Volume LPE events (`V`) | M8 | parsed; no volume events yet |
| Holdouts (`holdout;`, `ray:holdout`) | later | black, one warning |
| Filtered utility AOVs (Karma's ubox/idcover/zmin) | later, if comp needs it | pixel-centre first hit (D9) |
| Per-label NEE split of VEX closures (eval per bounce mask) | later | the VEX NEE contribution goes to the diffuse class (as the light multipliers already do) |
| Deep and checkpoint products | later | ignored |
| Denoised AOVs | M7 | the guides (albedo, normal) are already there |

### 2.3 Deviations from PLAN.md

None in content. PLAN.md names "crypto-matte" under the utility AOVs. Cryptomatte gets its own sub-step (M6.5), because it needs per-sample id tables and husk's extra-plane route, not the first-hit pass.

## 3. Architecture

### 3.1 Files

```
core/film/lpe.h                 runtime view (POD, NOVA_HOST_DEVICE): Program, step(), output lists
core/film/lpe_compile.{h,cpp}   parser (OSL + Karma), NFA, event DFA, minimization, alphabet compression
core/film/film.{h,cpp}          lpeSum per output, shadow pairs, crypto tables, first-hit utility buffers
core/film/crypto.{h,cpp}        MurmurHash3 + fixup, per-pixel id tables, ranking, preview colour, manifest
core/bsdf/closure.h             per-slot evalClosure, slot assignment, class selection in sampleClosure
core/integrator/wavefront.cpp   events and contributions at every site (lpe-design.md 2.4)
hydra/aov.{h,cpp}               AOV binding resolution: kind (beauty, LPE, raw utility, primvar, shader AOV, crypto, Hydra name)
hydra/renderBuffer.cpp          writes per kind; clear broadcast; GetResource() with UT_HUSDExtraAOVResource
hydra/renderDelegate.cpp        compiles the LPE program per binding change; lazy AOV copies
hydra/light.cpp, mesh.cpp, material/*   LPE tags, crypto names, shader AOV outputs
tools/nova_cli                  the same AOV kinds, crypto parts and metadata
houdini/tools/nova_settings.json, build_nova_hdas.py   the AOV toggles of the Nova Render Settings LOP
```

### 3.2 Per path and per pixel

| Data | Where | Size |
|---|---|---|
| LPE state | `WaveQueues::lpeState` | 2 B per path |
| NEE parts | `ShadowQueue`: first part, count, MIS weight; parts (state, value) side buffer | ≤ 6 parts per shadow ray |
| Slot per lobe | `ClosureList::lpeSlot[kMaxLobes]`; `Lobe::lpeKey` packed into the existing flags | 16 B per closure |
| LPE sums | `Film::lpeSum[output][pixel]`, `Film::lpeAux` for `shadow;` | 12 B (+12 B) per pixel and output |
| Crypto | per crypto AOV a fixed table of (id, weight) per pixel, 8 entries | 64 B per pixel |

## 5. Risks

| Risk | Mitigation |
|---|---|
| The product DFA explodes for exotic LPE sets | event-level construction, minimization and alphabet compression (prototype: 316 states for 30 rules); output groups beyond the guard |
| Class selection raises the noise of component AOVs | it changes only the hue of the beauty's samples; components are unbiased; measured per component |
| Karma's semantics differ where unmeasured (`B`, `shadow;`, sheen class, labels under tags) | probes in M6.3 before the reference scene is frozen |
| Film memory with many AOVs at 4K | 12 B per pixel and output; lazy copies; outputs that the DFA proves empty are not allocated |
| husk's extra-plane route changes with Houdini versions | the header is versioned with Houdini; a husk test checks the parts and keys |

## 6. Notes as built

Notes on M6.0 as built:
- `hydra/aov.{h,cpp}`: `HdNovaResolveAov` turns a binding into a kind (`Beauty`, `Lpe`, `Depth`, `PrimId`, `InstanceId`, `Normal`, `Albedo`, `None`), the LPE text without spaces, and `intAsFloat` (an int buffer with `husk:format float`/`half`). Hydra's names and Karma's `ray:hitPz`, `ray:primid`, `ray:hitN` already map; LPEs other than the beauty and every other source warn once and keep their clear value.
- `HdNovaRenderBuffer`:
  - a scalar clear value fills every channel;
  - ids into float images are written as floats, the background keeps the clear value (Hydra's int ids keep -1).
- `_RenderLoop` copies the beauty every pass; other AOVs every pass with at most 4 bindings, else after the first pass, once a second and at the end.
- **The `Facingratio_N` plane** (karma-aovs.md 4.4) is not Nova's: at husk's `Map()` Nova's buffer is all zero (traced), the EXR plane is not. husk produces it, apparently from the `N` plane Nova fills (`Facingratio_Ng` stays 0 while Nova fills no `Ng`). Revisited in M6.4, when Nova writes the facing ratio itself.
- Tests: `test_hydra` "Karma's render vars resolve to Nova's AOVs" (kinds, clear broadcast over stale data, float ids); the full Karma render-var scene renders in husk with 66 vars.

Notes on M6.1 as built:
- `core/film/lpe.h` (runtime, POD): `Program` with `symbol(type, scatter, tag, label)`, `step()`, per-state output lists, per-output flags; state 0 is dead. `core/film/lpe_compile.{h,cpp}`: the parser (OSL grammar with Karma's events A/B, positional `<type scatter 'tag' 'label'>`, prefixes `unoccluded;`/`shadow;`/`holdout(s);`, `!`, plus `?`), Thompson NFA, the concrete events grouped by which predicates accept them, subset construction over those groups, Moore minimization (the dead block renumbered to 0), and columns merged into the final classes.
- Tags and labels are program ids: the names any expression uses, 0 for everything else. With only the beauty or light groups, all scattering events fall into one class.
- Deviation from D3: beyond the limits (65 535 states, 1 MB) every expression fails with a message instead of splitting into output groups; no realistic set comes near it.
- Tests (`tests/test_lpe.cpp`): syntax errors per expression (others still compile); Karma's 30 authored strings; 4000 random paths × 44 expressions against an independent backtracking matcher over the parsed expressions (`lpe::matches`); shorthands, `'tag'` vs label positions, `.` never matching A/B; names that no expression uses collapse.

Notes on M6.2 as built:
- **Tables per pass.** `Renderer::lpeTables()` turns `RenderSettings::lpe` (a `shared_ptr<const lpe::Compiled>`) into `LpeTables` (`core/integrator/wavefront.h`): the program view, tag ids per mesh, material and light, and label ids per `LobeLabel`. They are rebuilt when the program or `Scene::version()` changes. Only coats, sheen and SSS carry label names (`lpeLabelName`: `coat`, `sheen`, `sss`); the other lobes are unlabelled, as in Karma. A new program re-sizes `Film::lpeSum` (`Renderer::setSettings`).
- **Events.** Each path carries a `uint16_t` state, set to the state after `C` when the camera ray starts.
  - Camera-visible area lights and environment lights each step to `L` with their light tag (`cameraAreaLight` now also returns the index; the light functions take a per-light sink).
  - Area lights crossed by scattered rays and escapes add one part per light; the parts take the clamp factor of the site's sum.
  - Emission steps to `O` with the object tag (the mesh's own tag, else its material's).
  - A light sample gives one part per lobe: R/T from the side of the geometric normal (SSS and translucency always T), D for every lobe except conductors and dielectrics, plus the label. Parts are merged by final state, stored with the shadow ray, and added if it is unoccluded, times the fake-caustic transmittance.
  - A continuation whose lobes at the sampled direction lead to different states picks one class with probability lum(f_k)/lum(f), from the new stream `stream::lpeSplit(depth)` (0x20000 + depth). The weight is multiplied by (f_k/f)/q_k per channel, and `diffuseShare` becomes the class's own.
  - Delta samples, single-lobe closures and closures whose lobes share one state keep the sampled lobe's event, and draw no extra number.
- **Deviation from D5's slot layout.** No `lpeSlot` table is stored in the closure. Events are computed per lobe when needed (the state after that lobe's event), and grouping by state happens where the parts merge and in the class choice. The results are the same and the closure keeps its size.
- **Accumulation.** LPE outputs are added straight into `Film::lpeSum` (tiles belong to one thread). The NaN/Inf check now runs per contribution, beauty included (`addRadiance`, `lpeDeposit`). The LPE variants of the closure and light queries are separate non-inlined functions, so shading without LPEs compiles as before.
- **VEX closures.** A light sample is one `D` event on the light's side; a continuation follows the sampled bounce class (SSS: `<TD>` with label `sss`).
- **Hydra.**
  - `GetLpeProgram()` collects the LPE bindings, deduplicates them and compiles once; the same expressions keep the same program, so rebinding does not restart. `SetAovBindings` maps each binding to its output and `!` to `invert`.
  - LPE buffers are written like the beauty (mean, alpha from the beauty for 4 channels) with the lazy copies of M6.0.
  - Hydra's `lpe:` AOV names resolve too.
  - Tags come from `inputs:karma:light:lpetag`, the constant primvar `karma:object:lpetag` (meshes and spheres, `HdNovaObjectLpeTag`) and `karma:lpetag` on a material's surface shader.
  - `unoccluded;`, `shadow;` and `holdout;` outputs warn once and stay black. `A`/`B` events come in M6.3.
- **Tests.**
  - `tests/test_lpe_render.cpp`:
    - a partition of `C.*[LO]` (10 expressions) sums to the beauty per pixel, unclamped, with the default clamp and with a hard clamp of 0.3;
    - light groups (`'key'`, `'env'`, the rest, `O`) sum to the beauty;
    - `C.*[LO]` and light-group sets leave the beauty bit-identical;
    - `C<RD>L`/`C<RG>L` equal the beauty with the light's specular/diffuse multiplier at 0, for every light strategy (light-only exactly, MIS and BSDF-only within 1 %);
    - object and material tags, the emission tag, and the coat and sheen labels.
  - `test_hydra`: one program per binding set, cached, with `!` and failed expressions.
  - `test_hydra_materials`: tags from USD, edits included.
  - `husk_aovs`: Karma's full render-var scene (`tests/scenes/karma_aovs.usda`, a copy of the probe scene) through husk. Karma's partition relations (karma_partition.txt) hold for Nova within 0.02 % of the beauty (half-float planes); the light groups and the coat are checked too.
- **Cost without LPEs:** none measurable. husk renders `cornell_rect` in 7.12-7.27 s with this build and 7.12-7.73 s with the installed M5 package, run alternately on the same machine. The LPE costs are measured in M6.6.

Notes on M6.3 as built:
- **A events.** Every lobe records its share of the closure's albedo at wo, split by side (`Lobe::albedoR/albedoT`, `ClosureList::addAlbedo` at all 22 push sites; `appendClosure` scales them with the segment weight). At a hit, a state whose A step leads to outputs (`LpeTables::albedoAfter`) gets, per lobe and side, the lobe's event, then A, with value throughput × albedo. VEX closures give their whole albedo as one `RD` event. A events come before fake caustics change the closure.
- **B events.** Every escape (camera rays included) steps to B with value throughput (no clamp). `!CB` is the alpha, and `!C<TG>*B` the alpha seen through glass.
- **unoccluded; and shadow;**
  - Light samples carry a second value per part, the light with MIS weight 1 (`ShadowQueue::partUnit`). It goes to the unoccluded sums whether the shadow ray is blocked or not, and also to shadow;'s lit sums (`Film::lpeLit`, one slot per shadow; output, `Compiled::shadowSlot`) if not blocked, times the fake-caustic transmittance.
  - With such outputs, shadow rays are traced even where the MIS weight is 0 (BSDF-only).
  - Lights that light sampling never picks (constant domes) get their unoccluded estimate from the continuation direction and their lit one at the escape, both with weight 1.
  - Camera-visible lights and emission seen by a path count as unoccluded and lit.
  - Hydra writes shadow; as 1 − lit / unoccluded per channel of the pixel's sums (0 where nothing is unoccluded).
  - **Measured rule:** nothing is light-sampled for the weight-1 sums into the inside of a solid dielectric (refraction in, reflection inside; closures with a transmitting dielectric lobe, inside = opposite the authored normal). Karma's `unoccluded;C<TG>L` is exactly 0 while light leaving the glass counts. Without the rule Nova's `unoccluded;C<TG>.*L` was +34 %; with it 0.96 and the unshadowed beauty 0.998 of Karma's.
- **Karma probes** (own husk instances, `common.usda` settings):
  - `C.*` = `C.*[LO]` in Karma too (S4);
  - `CB`/`!CB` agree exactly;
  - CDA 1.001;
  - Standard Surface sheen is `D` (`C<RD>.*` 1.000), but Karma gives it **no `'sheen'` label** (0): Nova dropped the label, so only coats (`'coat'`) and SSS (`'sss'`) are labelled.
  - Thin-walled glass: Nova reflects 1.9× Karma (`C<RG>`) and transmits 0.94×. This is Nova's physical two-interface sheet (M3 K2), not an LPE difference.
  - The probe scene with Karma's defaults (fake caustics, color limit 20) differs in shadows and indirect light for that reason. The reference scene therefore uses `common.usda`'s matched settings.
- **Reference `aov_components`** (`tests/reference`):
  - Scene: coat plastic, rough glass, a metal tagged `metal`, an emitter, a diffuse floor; key (rect) and fill (distant) tagged, a constant dome untagged.
  - Planes: 23 of Karma's standard vars (light groups, emission, unshadowed/shadow, the diffuse, glossy and transmission families, coat, a tagged custom LPE, the albedo family, `alphatransmission`), each compared to a Karma reference at 4096 spp.
  - Tooling:
    - `make_references.py` and `check_references.py` handle the manifest's `aovs` planes (`refcommon.extract_plane`, `plane_compare`);
    - the karma self check runs per plane;
    - the husk and nova_cli tests both pass.
  - Documented differences:
    - the coat ball: Karma's Schlick-fit coat, Nova's coat lobe +11 %, glossy +8 %, diffuse base −1.4 %;
    - the glass ball: the Schlick-fit dielectric, Nova's glossy reflection +15 %, `alphatransmission` +2.4 %, `C<TG>*DA` −5.7 %;
    - the metal ball: Karma's conductor albedo for A events stays nearer the base color, Nova blue +10 %, up to +26 % at the rim, while the metal's beauty agrees;
    - the shadow; planes: ratio planes, +1.4 % (beauty) and −2.8 % (diffuse) overall;
    - indirect diffuse −2..−4 % (light bounced off the coat ball);
    - rare-path planes (indirect emission): larger absolute tolerance, since Karma fails its own 64-spp check with the defaults.
  - Everything else agrees within the default statistics: the beauty, light groups, direct diffuse, `unoccluded;C<RD>L`, emission, `metal_glossy`, the albedos off the balls.
- **husk_aovs** adds the probe scene's relations: unoccluded > beauty; shadow ≈ 1 − C/U within 0.02; CDA = albedodiffuse; `!C<TG>*B` ≤ alpha and within 0.03 of it.
- **Tests (`test_lpe_render.cpp`):**
  - shadow;/unoccluded; with a delta sun and an occluder (exact 0 and 1, the unshadowed value under the occluder);
  - a constant dome under a roof (unoccluded unchanged, shadow; 1);
  - unoccluded sums equal the beauty's components without occluders for MIS, light-only and BSDF-only;
  - `CB` + alpha = samples per pixel, and `.` never matches B;
  - `CDA` is the albedo exactly, and diffuse + glossy albedo equal the first-hit albedo.

Notes on M6.4 as built:
- **Utility planes.**
  - The host asks for planes through `RenderSettings::utility` (a list of `UtilityRequest`, `core/film/film.h`). `Film::utility` holds them and `renderFirstHitAovs` fills them at the pixel-centre first hit (`FirstHitUtility`). Ids are stored as floats, −1 on the background.
  - Hydra resolves Karma's sources: `ray:hitP`, `ray:hitP_camera` (and Hydra's `Peye`), `ray:hitN`, `ray:hitNg`, `ray:hitN_camera`, `ray:hitNg_camera`, the two facing ratios, `ray:hitdist`, `ray:primid` and `ray:element` (both the face index), `ray:motionvector`, `ray:velocity`, `AO`, `export_basecolor`, sourceType `primvar` (and Hydra's `primvars:<name>`), Hydra's `elementId` and `Neye`, and `ray:objectid` (the Hydra prim id).
  - Other raw names are shader AOVs; a material without them gives 0, as in Karma.
- **Karma's conventions, measured** (own husk probes, `ray:*` help in kma_rayimport):
  - `P_camera` in camera space looking down −Z;
  - `N`/`Ng` as authored, not turned to the viewer (Hydra's `normal`, the denoiser guide, stays turned);
  - facing ratio |N·I|;
  - `hitdist` from the eye (not the near plane; orthographic cameras: the planar depth);
  - `ray:primid` = `ray:element` = the polygon index within the gprim (`MeshDesc::triangleFaces` from Hydra's triangulation, subdivision and dicing);
  - `motionvector` = the raster displacement over the shutter, pixels, y up; `velocity` = the world displacement over the shutter (Karma averages them over pixel samples, background as 0);
  - `AO` = the unoccluded fraction of one cosine ray per pixel sample, with no distance limit (a roof 500 units up still occludes fully). Nova accumulates it per sample at the camera hit (`WaveQueues::aoRays`, stream 0x30000), filtered like the beauty.
- **Material AOVs.** The translator turns a surface shader's `aov:<name>` inputs (where Houdini puts kma_aov's custom inputs) into outputs behind the fields in use (`IrGraph::aovs` → `Program::aovs`); the shader AOV planes read them at the first hit. `export_basecolor` is the base color field of the native models.
- **VEX materials:** the first-hit albedo now comes from the bridge (it was black since M5).
- **husk and int render vars.** An int var with `husk:format float` (Karma's `primid`, `element`) came out of husk as garbage gradients, whether the int buffer held ints or float bits. The M6.0 note "husk copies the bytes" holds only for some values. When the binding asks for a float image, the buffer now reports `HdFormatFloat32` and holds floats (`HdNovaRenderBuffer::ReportFloatIds`), and husk writes them exactly. The same fix makes `ray:objectid` work.
- **Differences / deferred (deviations from D9):**
  - VEX `export_*` parameters of bridge materials are not AOVs yet; it needs an export path in the CVEX bridge, and PLAN.md does not list it.
  - Meshes without `st` give 0 in the `st`/UV AOV, while Karma gives the face's parametric coordinates.
  - `ray:objectid` is the Hydra prim id, where Karma uses its own hash-like ids.
- **Tests.**
  - `test_utility_aovs.cpp`: analytic P/P_camera/normals/facing/hitdist/face ids/st/base color/background, authored normals on a turned-over quad, motion vectors and velocity over the shutter (orthographic, 4 px per unit, y up), AO under roofs at 0.5 and 50 units.
  - `test_hydra`: the name resolution.
  - `test_hydra_materials`: a material AOV end to end.
  - `husk_aovs`: `tests/scenes/utility_aovs.usda` (Karma-style vars, int ids with `husk:format float`) checked against the geometry; all exact except AO, which is statistical.

Notes on M6.5 as built:
- **Ids.**
  - `core/film/crypto.{h,cpp}`: MurmurHash3_x86_32 (seed 0) plus the specification's exponent fixup, the float bits as image values, and the preview colour (h, h≪8, h≪16)/2³².
  - The scene stores ids, not names:
    - `MeshRecord::cryptoObject` (the object name);
    - `MeshRecord::cryptoAttributes` (constant or per-face string/int primvars; ints as decimal strings);
    - `MaterialDesc::cryptoId` (the material path; the default material's is `defaultshader`).
- **Names (Hydra, `hydra/crypto.{h,cpp}`), as Karma's:**
  - objects: the `HdPrimOriginSchema` scene path; for native instances the instancer's first `instanceLocations` entry plus the prototype-relative path; point-instancer prototypes keep their own path;
  - materials: the bound material's path, per GeomSubset face;
  - primvars: string or int values.
  - `HdNovaCryptoNames` (in the render param) maps ids back to names for the manifests.
- **Coverage.** Each camera sample adds weight 1 for its first surface's ids. Stochastic opacity has already picked that surface, so each id gets its opacity share in expectation. A pixel keeps 8 (id, weight) slots per cryptomatte (`CryptoPlane`), and further ids are dropped. Every slot is filtered like the beauty (filter importance sampling), so the coverage sums to the alpha exactly.
- **Output.**
  - A binding with `karma:cryptomatte` (or the unprefixed name) becomes `HdNovaAovKind::Crypto`. Its own buffer gets the preview colour over all ids.
  - `GetResource()` hands husk a `UT_HUSDExtraAOVResource` with ⌈rank/2⌉ RGBA planes `<var>NN`, pairs sorted by coverage and cut at the rank. The metadata are `cryptomatte/<7 hex of mmh3(var)>/name|hash|conversion|manifest`, plus `manif_file` for a sidecar, which husk writes next to the product.
  - The manifest lists the ids in the image.
  - nova_cli reads the same resource and writes the same parts, header keys and sidecar.
- **Measured against Karma:**
  - `tests/scenes/karma_aovs.usda` (Karma's own crypto vars): the same layer keys and manifests (7 objects, 7 materials), coverage = alpha exactly, previews exact (`docs/research/m6/probes/crypto_analyze.py`).
  - `tests/scenes/crypto.usda` (point instancer, native instances, GeomSubsets, unbound geometry, string and int primvars, a sidecar, ranks 6/3/2): Nova's manifests equal Karma's entry for entry, including the fixed-up `/World/inst/protos/rock` (8082046e).
- **Not done:**
  - per-instance primvar cryptomattes on point instancers (Karma supports them);
  - Karma's deterministic opacity shares: Nova's are stochastic, equal in expectation.
- **husk detail:** husk derives the sidecar's directory from the product path up to the last "/". A path with mixed separators puts the file one directory too high, so the test uses forward slashes.
- **Tests:** `test_crypto.cpp` (Karma's hash vectors incl. the fixup; coverage by object, material and per-face primvar, sum = alpha at a seam); `husk_aovs` checks `crypto.usda` written by husk and by nova_cli: metadata keys, manifest names, rank layers, ids, coverage sum and sidecar.

    - the beauty;

- **Copies, as D11 designed them.** AOVs other than the beauty are copied from the film:
  - after the first pass;
  - at convergence;
  - after a pass in which a reader mapped them (`HdNovaRenderBuffer::TakeMapRequest`, set by `Map()` and `GetResource()`).

  The viewport's shown AOV and husk's monitor stay live, and unread buffers cost nothing. This replaces M6.0's rule ("every pass with up to 4 bindings, else once a second"). With 74 LPEs on `cornell_rect` those copies took 0.21 s.
- **LPE cost (deviation from the step's gate).** `docs/benchmarks.md` has the table: Karma's standard set costs +5.9 % (`cornell_rect`), +9.5 % (`mtl_glass`) and +13.2 % (`mtl_spheres`); the gate was at most 5 %. The beauty-only gate holds, because without LPE bindings no LPE code runs.
  - Profiling (`nova_cli --profile`, `tools/nova_cli/sampler.cpp`, built for this) and switch experiments that disabled one part at a time showed bookkeeping spread over many sites, with no single hot spot. The sites are listed in benchmarks.md.
  - Kept:
    - closures whose lobes lead to one state on each side skip the per-lobe evaluation (`lpeNeedsLobes`; single-lobe closures and uniform ones; with `unoccluded;`/`shadow;` outputs, glass stays per lobe for the into-solid rule);
    - per-state output lists by kind (`LpeTables::plainOuts`, `unitOuts`, `litSlots`);
    - forced inlining of the event helpers.
  - Rejected: a pixel-major LPE film was slower with 74 outputs.
  - Further gains would need a different storage of the parts and deposits; that is left for the performance work of M7 and M10.
