# M11 P4: Light filters, Karma's Blocker Light Filter

Package P4 of [M11](M11.md): the Karma Blocker Light Filter LOP (`karmablockerlightfilter`) renders in Nova as in
Karma, on CPU and XPU. Research: [karma-lops.md](../research/m11/karma-lops.md) (row "Karma Blocker Light Filter",
K4, section 2); light linking: [M9.md](M9.md) D15.

## 1. What the LOP authors

A `KarmaBlockerLightFilter` prim (base `UsdLuxLightFilter`, Hydra sprim `lightFilter`) with `inputs:shape`
(`sphere`, `capsule`, `box`), `radius` (sphere, capsule), `width`/`height`/`depth` (box; capsule: `height`),
`roundedcorner` (box), `falloff`, `intensity` (the LOP writes 0 = full block; the schema fallback is 1),
`exposure`, `tint`, `invert` (int), `space` (a string, by default a reference to the node's prim path), the
shader ids `lightFilter:shaderId` and `kma:lightFilter:shaderId` = `kma_lfilter_blocker`, its transform, and a
`filterLink` collection the LOP authors as `includeRoot = 0` with no includes. Lights point at filters with
`light:filters` (the LOP does not; the Light LOP or the Light Filter Library does). The LOP has no falloff curve:
`falloff` is a width only.

## 2. Karma's behaviour (measured)

Isolated hython built probe scenes with the actual LOP (scratch `m11_p4/make_probes.py`); isolated husk rendered
them with Karma CPU 22.0.466 (16 samples, box pixel filter). A grey ground seen straight down by an orthographic
camera (8 x 8 units, 40 px per unit) and lit by a delta distant light straight down shows the factor itself. The
checked-in subset is `tests/scenes/karma_filters/` (section 6).

| Question | Karma |
|---|---|
| Which point is tested | **The shading point only.** A blocker over half of a rect light (not reaching the ground): no change anywhere (lit fraction 1.0000). A blocker between light and ground: no change. A blocker containing the ground: blocked. |
| Light samples and BSDF rays | Both: a rect light and a dome are blocked to exactly 0 at a blocked point. |
| Mirror reflections (delta BSDF rays) | Blocked at the **mirror point** (a blocker around the mirror point: reflection 0; around the light only: unchanged). |
| Camera-visible lights | Blocked at the **camera ray's origin**: a blocker around the orthographic camera's centre blacks the light where the rays start within it and leaves the corner rays (origin 1.34 from the centre) at full value; one around the light only changes nothing. Alpha stays 1. |
| Shapes | Box: width, height, depth along local X, Y, Z. Capsule: a segment of length `height` along local Y, `radius` around it. All in the filter's space (a scaled filter scales the shape and its falloff). |
| Falloff | `u = smoothstep(-f, f, s)`, the light that passes, with `s` the signed distance to the shape **in units of the shape's size**: the radius (sphere, capsule) or the box's **smallest half extent**. `f = min(falloff, 1)` (1.5 renders as 1). Sphere r 1, f 0.5: 0.0352, 0.2321, 0.5189, 0.7996, 0.9784 at d 0.61, 0.81, 1.01, 1.21, 1.41; r 2, f 1: 0.5047 at 2.01; box 4 x 6 x 5, f 0.5: zone [1, 3] along X and [1.5, 3.5] along Z (half width 1 = 0.5 x 2). |
| Rounded corner | A rounded box (corner radius `min(roundedcorner, 1)` x the smallest half extent): 0.5 on a 3 x 2 x 2 box rounds by 0.5, 1.0 on 4 x 6 x 5 by 2, 1.5 on 3 x 2 x 2 by 1, 0.5 on 3 x 0.5 x 2 by 0.125. |
| Intensity, exposure, tint | Factor `k + (1 - k) u` with `k = intensity x 2^exposure x tint`: intensity 0.5, exposure 1 gives 1.0 inside; tint (1, 0.5, 0.25) at intensity 0.5 gives (0.5, 0.25, 0.125). |
| Invert | `u -> 1 - u`: intensity 2 inverted gives 1 inside, 2 outside. |
| Several filters on a light | Their factors multiply (0.5 x 0.5 = 0.25; inverted 0.25 with 0.5: 0.125). Other lights stay unfiltered. |
| `space` | Its own prim (default) or another light filter: the inverse of that prim's transform. A camera: the inverse of the camera's. **A light: the light's transform itself, not its inverse** (a sphere light at (-2, 0, 1) scaled 1.5 gives a disk of radius 0.667 at (1.33, -0.67); a rotated rect light confirms it). Geometry, an Xform, an unknown path, `""`, `space:world`, `space:object`: world space (the filter's own transform ignored). `space:camera`: the render camera. |
| Filter prim visibility | Ignored (an invisible filter still blocks). |
| `filterLink` | **Ignored**: a radius-50 blocker limited to sphere A blocks everything, with explicit includes, `expandPrims`, the LOP's own collection pattern, a membership expression, or `includeRoot` with excludes. |

## 3. Decisions

| # | Decision |
|---|---|
| F1 | **Core.** `LightFilterData` (core/lights/light_filter.h): the world-to-space affine map (floats), the shape normalised as measured (half extents, corner radius, 1 / size, falloff), invert, `k`, and a filterLink bit. `LightData` gets `filters`/`filterCount` (a pointer into the scene's array, re-pointed on the GPU like textures). `lightFilterProduct(filters, count, site)` multiplies the factors at a `LightFilterSite` (the point being lit and its receiver set's categories). `LightFilterKind` is the extension point for further kinds. |
| F2 | **Where it applies**, in the shared NOVA_INLINE code (CPU and XPU identical): `sampleLight` (every light sample: surfaces, volumes, SSS exits, equiangular), `areaLightsAlongRay`, `escapedRadiance`, `sampleShadowLinkedDome` and `lpeUnoccludedEnvironment` at the ray's **gather site** (`gatherSite()`: the MIS vertex `prevP` after a non-delta event, which is where its light sample was drawn, so both MIS strategies see the same factor; the ray's origin after a delta event, so a mirror filters at the mirror point), `cameraAreaLight` and `cameraEnvironment` at the camera ray's origin. MIS weights stay those of the unfiltered light. Emissive triangles and volume lights have no filters. Scenes without filters run the same instructions on the same values (bit-identical golden). |
| F3 | **Selection.** A light's selection weight (power table and light tree) is multiplied by the product of its filters' bounds `max(1, max|k|)`, so filters that brighten (intensity or exposure above 1, inverted ones included) keep the light's share of samples; blockers that only darken leave it unchanged (identical samples). The tree's bounds stay valid (filters never make light where the unfiltered light has none). Karma keeps filtered lights out of its tree; that changes noise only. |
| F4 | **Scene.** Filters are keyed (Hydra: the prim path): `Scene::setLightFilter`/`removeLightFilter`; `LightDesc::filters` lists keys in order and the scene resolves them at commit, so lights and filters may sync in any order; missing keys are skipped. A filter edit rebuilds the light records (cheap). |
| F5 | **Hydra.** `HdNovaLightFilter` (sprim `lightFilter`): the kind from `kma:lightFilter:shaderId`, `lightFilter:shaderId` or the material network's node; inputs from the light parameters (with or without `inputs:`) or the network's node, unauthored ones at the schema's fallbacks; the transform; the space as measured (F2 table), including Karma's convention for lights; `filterLink` is not read (F6). Other kinds (gobo, barn doors, gel, attenuation, ...) warn once per kind and are left out; unknown named spaces warn once. `HdNovaLight` reads `filters` (`light:filters`). |
| F6 | **filterLink: ignored, as Karma 22.0.466 ignores it** (section 2; M11's principle that Karma's measured behaviour is the reference): every blocker acts on every object, whatever its collection says, and Nova's light-linking scene index keeps light filters out of its types. The core keeps the mechanism UsdLux's `filterLink` would need (a filter's link category, numbered with the light-link categories, 64 in all; a filter acts at a site whose receiver set holds its bit; the camera has none; volume events are set 0), tested in the core and on the GPU. Should Karma start honouring it, Nova would add `lightFilter` to the light-linking scene index's filter types (`hydra/implicitSurfaceSceneIndexPlugin.cpp`) and set `LightFilterDesc::link` from the category it gives (`HdTokens->lightFilterLink`) in `HdNovaLightFilter::Sync`: a one-line change each. Then the LOP's default collection (nothing included) needs care: the scene index gives it a category of an empty expression, which matches no object, whereas Karma blocks every object. |

## 5. Limits

- Only the blocker; Karma's other filter VOPs (gobo, barn doors, gel, attenuation) warn and are ignored.
- `space:camera` (the render camera) warns and uses world space.
- A blocker whose space is another prim follows that prim's transform at the filter's sync; moving only the
  space prim in an interactive session does not re-sync the filter (edit the filter, or re-render).
- Filters on lights under point instancers apply per instance in world space (one record list per light).

## 7. Notes

- Measurement scripts (scratch `m11_p4`): `make_probes.py` (hython, 75 probe scenes), `render.py` (isolated husk),
  `a1.py` ... `a8.py` (analysis). The LOP's `space` parameter references `primpath`: setting it from Python needs
  `set(value, follow_parm_reference=False)`, or the prim path itself changes.
- With `lightFilter` among its filter types, `HdsiLightLinkingSceneIndex` gives a filter's `filterLink`
  collection a category (`light` container, `lightFilterLink`) and the geometry the category, as for lights; an
  empty collection gets a category of an empty expression (it would match nothing). The scene index only
  categorises prims it sees arrive: a test harness must build the chain before the stage populates it (husk and
  the viewport do). The Hydra test uses such a chain to show that Nova ignores the category.
- A first version applied filterLink as UsdLux defines (with the LOP's empty collection acting on every object);
  the coordinator decided to follow Karma (F6). Karma's `link_A` row (blocker limited to sphere A: everything
  blocked) is now asserted.
- In `nova_hydra_tests` a `Camera` prim is not imaged as a camera (empty prim type), so the camera space is
  checked through husk (`space_cam2`).
- Karma (and Nova) keep a light's unfiltered MIS weights; a blocked shading point gets exactly 0 from both
  strategies, so blocked regions are noise-free.
