# M11: Compatibility with Karma's Solaris nodes

Goal (user, 2026-11-05): Nova renders scenes built with the **Karma LOP nodes of Solaris** ("die Nodes mit Karma * in
Solaris, mehr nicht") as Karma does, on CPU and XPU: the twelve visible LOP types whose label starts with "Karma"
(versions included). Not in scope: Karma's shading VOPs and material recipes, the Labs nodes, hidden or deprecated
types (Karma Ocean, Procedural, Toon Shading, the v1 Karma and Karma Render Settings), the Karma ROP/TOPs. M11 goes
beyond docs/PLAN.md (M0-M10); this document is its plan.

Research (measured with isolated hython and husk, Karma CPU as the reference): the node inventory is
[karma-lops.md](../research/m11/karma-lops.md); the properties the Karma Render Settings LOP authors are inventoried in
[karma-properties.md](../research/m11/karma-properties.md) (its section 1 dumped the hidden v1 node: re-measure the
defaults with `karmarendersettings`); [karma-vops.md](../research/m11/karma-vops.md) covers the VOPs (out of scope
except where a node below builds a shader, e.g. the Fog Box's `kma_volume` and the Background Plate's material).

## Principles

- **Karma's measured behaviour is the reference**: each package measures Karma first (isolated husk), implements,
  then compares (ratios in `tests/husk/check_*.py`, reference scenes in `tests/reference`), on CPU and XPU.
- **Nova's own settings win; Karma's are the fallback** ("Unset: Karma's ..."), decided by whether the Nova setting
  is authored, not by comparing with its default.
- **CPU and XPU identical**; integrator features go into the shared NOVA_INLINE headers.
- **Nothing silent**: a Karma setting or node feature Nova does not support warns once, naming it.

## Packages, in order

Effort per device: S <= 1 day, M 1-3 days, L more.

| # | Package | Nodes | Effort |
|---|---|---|---|
| P1 | **Karma Render Settings, core**: every parameter of the node with a Nova equivalent read as a fallback (sampling and pixel oracle, seed, pixel filter, ray limits incl. per object, dicing, texture width/blur, DOF/motion switches, curve/point style tokens, emission-as-light and motion defaults); Karma's defaults where Nova differs today: fake caustics (`causticsenable`) with Karma's factor and knobs, `causticsroughnessclamp`, `internalreflectenable`, `constrainmaxrough`, colour limits; a once-per-stage warning for each image-changing setting still unsupported | Karma Render Settings | L (1.5-2 weeks) |
| P2 | **Holdouts and ray visibility**: `rendervisibility` per ray type (Embree filter, OptiX any-hit, first-hit AOVs, cryptomatte), `holdoutmode` Matte and Background (shadow alpha, the holdout LPE planes), the related settings (`use_background`, `bgoccludeshadow`, lights' `illumbackground`), `transformvector` spaces in the translator, Houdini `.pic` images | Shadow Catcher, Background Plate 1.0/2.0, Render Settings' visibility controls | L (2 weeks) |
| P3 | **Karma sky**: register Hydra's `light` sprim, build Karma's sky model into Nova's textured dome (importance sampling, light tree, XPU unchanged), ground and horizon blur, camera visibility; the Physical Sky's sun is its DistantLight | Sky Dome Light, Physical Sky (sky mode) | M (1 week) |
| P4 | **Light filters, blocker**: a `lightFilter` sprim, `light:filters`, `filterLink`; per-light filter list in the core applied to light samples, BSDF hits on lights and camera-visible lights; the blocker (shapes, rounded corner, falloff, invert, intensity/exposure/tint, its space) | Blocker Light Filter | M (1 week) |
| P5 | **Fog Box**: gprims whose material has only a volume output (or `volumeuniform`) become media bounded by their surface (invisible shell, inside traced with M8's tracking, shader evaluated inside: `ray:hitP`, geomprop fallback, `ray:isshadowray`), camera inside the box, nested/overlapping shells; answers M8's open decision | Fog Box | M-L (1-2 weeks) |
| P6 | **Products and vars**: per-var `karma:filter` (`minmax` zmin/idcover, `stats` var/mse, `ubox`), missing raw sources (`ray:mask`, ...), checkpoint products, deep camera maps (`karma:deep`), per-instance primvar cryptomattes | Render Products, Standard Render Vars, Cryptomatte | M + L (deep) |
| P7 | **Sky atmosphere**: a planetary medium (Rayleigh, Mie, absorption layer, ground) lit by the distant lights; the gprim type Houdini emits; Physical Sky's atmosphere mode | Sky Atmosphere, Physical Sky (atmosphere mode) | L (3+ weeks) |
| P8 | **Texture baking**: a UV-space bake mode (low/high/cage, ray bias and distance, UDIM tiles) and the maps (tangent normal with MikkT, alpha, AO, curvature, cavity, thickness, edges, rounded normals, position, shader exports), padding and the normal remap filter | Texture Baker | L (3+ weeks) |
| P9 | **Karma Render Settings, advanced**: the node's remaining image-changing features, each measured against Karma: outlines (27 settings), nested dielectric priorities, path guiding, look-dev overrides (headlight, AO, fog), portal settings (P9a: outlines and look-dev overrides, [M11-P9a.md](M11-P9a.md)) | Karma Render Settings | L each |

P1-P5 run in parallel (separate worktrees; P1 and P2 share some Hydra primvar code), then P6, then P7/P8/P9.

Decisions taken with the recommendations of the research (no answer needed to start): holdouts match Karma exactly,
including what secondary rays see; the Fog Box gets mesh-bounded media; Karma's variance mode maps onto Nova's pixel
oracle (primary x secondary samples, variance threshold).

## Verification

- `tests/husk/check_karma_nodes.py`: a USDA per node (built once by hython from the Karma LOP with defaults and with
  representative settings, checked in), rendered with Nova; Karma's values measured once and stored in the script, as
  `check_lights.py` does. Pass: within 3 % of Karma, exact where analytic (holdout alpha 0, blocker black).
- Reference scenes for spatial results (shadow catcher alpha, blocker falloff, sky, fog box, baked maps) via
  `tests/reference/tools/make_references.py`.
- Hydra tests for the new sprims (`light`, `lightFilter`); `tests/houdini` cases that create each Karma LOP and render
  with husk + Nova (catches LOP changes in future Houdini builds); viewport checks for sky, filter and fog box;
  `[gpu]` cases per integrator feature; the golden check.
