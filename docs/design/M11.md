# M11: Compatibility with Karma's nodes

Goal (user, 2026-11-05): "make it compatible with all Karma nodes". A scene built with Karma's nodes (shading VOPs,
material recipes, LOPs, the Karma tabs of the generic LOPs, the ROP/TOP route) renders in Nova as in Karma, on CPU
and XPU, or Nova says clearly what it does not support. M11 goes beyond docs/PLAN.md (M0-M10); this document is its
plan.

Research (measured with isolated hython and husk, Karma CPU as the reference):

| Report | Scope | State today |
|---|---|---|
| [karma-vops.md](../research/m11/karma-vops.md) | 45 visible `kma_*` VOP types, 11 recipes | 16 supported, 16 partial, 13 missing; recipes 2 / 6 / 3 |
| [karma-lops.md](../research/m11/karma-lops.md) | 19 LOP/ROP/TOP/SOP types (30 versions), Karma (Setup), Karma tabs of 7 generic LOPs | 1 works, 2 nearly, 7 partial, 7 wrong or nothing, 3 cannot use Nova |
| [karma-properties.md](../research/m11/karma-properties.md) | 212 render properties | 14 honoured, 18 as fallbacks, 6 warned, 174 silently ignored (125 change the image) |

Note: karma-properties.md section 3 dumped the hidden v1 `karmarenderproperties` LOP; the current
`karmarendersettings` authors other defaults (colour limit 20, `husk:default_delegate`). WP1 re-measures those
defaults with the current LOP before mapping them.

## Principles

- **Karma's measured behaviour is the reference**, as in M1-M10: every package starts by measuring Karma (isolated
  husk), then implements, then compares (ratios in `tests/husk/check_*.py`, reference scenes in `tests/reference`).
- **Nova's own settings win; Karma's names are the fallback** (the existing "Unset: Karma's ..." pattern). Fix the
  caveat that an explicit Nova value equal to its default loses to Karma's (Hydra hands Nova the descriptor default):
  read whether the Nova setting is authored, not its value.
- **CPU and XPU identical**; integrator features go into the shared NOVA_INLINE headers.
- **Nothing silent:** a Karma node or property Nova does not support yet warns once (per scene and name), with the
  node or property named. The Nova Material Builder TAB menu hides only what does not render.

Order rationale: WP1 changes how every Karma-built scene looks and is mostly Hydra work; WP2-WP5 are the
compositing, outdoor and look-dev lighting tools that give visibly wrong frames today; WP6-WP8 close the remaining
default-scene and shading differences; WP9-WP13 serve narrower workflows; WP14-WP15 are features of their own.

Not planned (no image effect or Karma-internal): engine/bucket/cache/thread settings, internal ids, Karma's
ray-splitting controls (only their total sample counts map, WP1), the biased volume step settings (Nova stays
unbiased, M8 D16).

## Verification

- `tests/husk/check_karma_nodes.py` and `check_karma_props.py`: a USDA per node or property (built once by hython and
  checked in), rendered with Nova; Karma's ratios and alphas measured once and stored in the script, as
  `check_lights.py` does. Pass: within 3 % of Karma, exact where analytic (holdout alpha 0, blocker black, exposure).
- Reference scenes for spatial results (shadow catcher alpha, filter patterns, sky, fog box) via
  `tests/reference/tools/make_references.py`.
- Hydra tests for the new sprims (`light`, `lightFilter`); `tests/houdini` cases that create each Karma LOP with
  defaults and render it with husk + Nova; viewport checks for sky and filters; `[gpu]` cases per integrator feature.

## Decisions needed before WP1

1. **Scope**: all fifteen packages, or stop after WP1-WP13 and plan WP14/WP15 (outlines, path guiding, nested
   dielectrics, portals, sky atmosphere, texture baking) separately? Recommended: WP1-WP13 now.
2. **Holdouts**: match Karma exactly (measured, including what reflections see). Recommended.
3. **Fog Box**: implement mesh-bounded volumes (WP7). Recommended.
4. **Nova ROP/TOP** (WP9): ship them. Recommended (small, opens `/obj` and PDG workflows).
5. **Sample counts**: map Karma's variance mode (primary x secondary samples, variance threshold) onto Nova's pixel
   oracle, not only the total. Recommended.
