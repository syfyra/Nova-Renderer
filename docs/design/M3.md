# M3 design: shading core

ShaderGraph IR, bytecode VM, Standard Surface / OpenPBR, OIIO textures.
Milestone result per `docs/PLAN.md`: **"MaterialX-Standard-Surface aus Solaris rendert korrekt"**.

This document is the binding M3 design. It merges three independent drafts
(`docs/research/m3/plans/plan-{fidelity,incremental,gpu-perf}.md`), which agree on
almost every decision; where they differ, section 1 records the choice. Formulas,
tables and measured numbers that are not repeated here are taken from the drafts and
the research reports in `docs/research/m3/` (validated prototypes in
`docs/research/m3/prototypes/`). Where this document and those files disagree, this
document wins.

"Renders correctly" means:
- the network renders through Nova's own IR and VM;
- it matches Karma CPU wherever Karma follows the MaterialX definition;
- where Karma deviates from the definition, Nova is analytically exact, and the
  deviation is documented and tolerated per image region in the reference tests.

## 1. Decisions

| # | Decision | Source / reason |
|---|---|---|
| K1 | **Intrinsic uber closures.** Standard Surface 1.0.1 (+1.0.0 defaults), OpenPBR 1.1.1, `surface_unlit` and UsdPreviewSurface are not expanded. Their inputs bind to a POD `SurfaceParams` block; `buildSurfaceClosure()` turns it into a flat list of at most 8 lobes from one lobe library. Generic pbrlib BSDF graphs follow in M4 (`SurfaceModel::LobeList`). | all three drafts; lobe-exact importance sampling, GPU-friendly (Cycles SVM "principled" pattern) |
| K2 | **BSDF physics = MaterialX graph semantics + exact per-microfacet Fresnel + LUT energy compensation.** Karma's approximations (Schlick-fit dielectric, Lambert-shaped sheen, sRGB thin-film matrix, uncompensated rough glass) are measured and tolerated, not copied. | all three |
| K3 | **Pattern nodes follow Karma's semantics** (VEX safe math, ramptb/splittb orientation, dodge/burn, `constant` address mode = black, heighttonormal as world-space bump). No MaterialX-"spec" switch in M3; one instruction flag bit stays reserved for it. | incremental + gpu-perf (fidelity proposed a switch) |
| K4 | **All other MaterialX nodes are expanded at translation time** with Houdini's MaterialX 1.39.5 C++ API: an own `HdMaterialNetwork2 → mx::Document` with `setDataLibrary` (0.18 ms, never hdMtlx's 18 ms deep copy), `flattenSubgraphs(filter)`, `topologicalSort()`. MaterialX is linked only by `hydra/`. | all three; Karma expands the same graphs |
| K5 | **One op semantics, two executors.** `core/shading/ops.h` (`NOVA_HOST_DEVICE`) is used by a 32-lane SoA batch executor (CPU shade stage, `runBatch<8/16/32>`) and a per-lane executor (`vm_lane.h`: CUDA in M10, Embree filter callbacks, host prologue, test oracle). Both are bit-identical. | all three; measured 0.15 ns/(instr·lane) at N = 32 vs 3 ns per lane |
| K6 | **Parameter values never fold.** Per-material uniform block (4 zero slots, constants, params, hoisted). Parameter-only subgraphs are hoisted into a host prologue. A **structure hash** decides program sharing; a value edit keeps the hash and never recompiles. Texture paths go through a per-material slot table, so a path edit is a value edit too. | all three |
| K7 | **Derivatives by shifted re-evaluation.** The compiler clones the varying cone of every `Tex2D` texcoord input and every bump height input twice, with globals shifted by the footprint vectors; derivative = difference. No dual variant of any opcode. | incremental + gpu-perf (fidelity proposed dual rows for texcoords); one mechanism for textures and bump, every op covered |
| K8 | **Ray cones** (2 floats per path) give the footprint; `nova:textureFilterWidth` = 0.25 reproduces Karma's measured MIP choice (level = log2(texels per pixel) − 2). | all three |
| K9 | **Textures:** a private OIIO `TextureSystem` on the shared `ImageCache` (`flip_t=1`, `gray_to_rgb=1`, `stochastic=3`). Anything not linear, tiled and mipped is converted once to a half-float, linear, tiled, mipped EXR in a disk cache (OIIO's `colortransformid` is wrong for untiled/automip inputs and quantizes 8-bit data). Linear gamut changes are a 3×3 matrix after the lookup. UDIM follows Karma. Light textures (dome, rect) keep the full-image `HdNovaTextureCache` but share the color-space decision. | all three |
| K10 | **Opacity in accelerator filter callbacks.** An opacity-only program (DCE to the opacity output) runs in Embree argument filters for closest-hit and occlusion queries, with a hash-based stochastic decision per (ray seed, mesh, prim, instance). Installed only on meshes whose materials have opacity. Maps 1:1 onto OptiX any-hit. | all three |
| K11 | **Network source:** read `HdMaterialSchema` from the terminal scene index (keeps `colorSpace`/`typeName`, terminal output names, `nodeTypeInfo`), `GetMaterialResource` as fallback. Context chain per material `nova → kma → mtlx → ""` (universal); `vex` joins in M5. | all three; without `kma` the Karma Material Builder renders nothing |
| K12 | **All numeric primvars are uploaded** as generic mesh attributes (and instance attributes), remapped per (mesh slot, material) at commit. GeomSubsets give per-triangle material slots. Material edits never touch meshes or the BLAS. | all three; `HdMaterialNetwork::primvars` is always empty, material edits never re-sync meshes |
| K13 | **All ωo-dependent factors** (layer albedos, compensation, thin-film albedo, lobe picks) are computed once in `buildSurfaceClosure`; `evalClosure`/`sampleClosure` need no LUT lookups. | gpu-perf |
| K14 | **GPU guard from the start:** a compile-only `nvcc` target (label `cuda`) includes every kernel-side header (`core/math`, `core/bsdf`, `core/shading/{program,ops,vm_lane,noise}.h`, `core/texture`). Kernel-side code has no STL containers, virtuals, exceptions, recursion, host statics or `double`; fixed sizes only (8 lobes, ≤ 4 texture channels, bounded extension words). A float that a shader or the scene drives is converted to an int with `toInt` or `clampToInt` (`core/math/common.h`), never with a plain cast: out of int's range and for NaN the cast is undefined, and x86 (INT_MIN) and CUDA (saturation, NaN to 0) disagree there (bug audit S-1). | gpu-perf; enforces PLAN.md's GPU rule continuously |
| K15 | **Register file:** rows of floats, `R[row·32 + lane]`. `CompileOptions::maxRows` = 1024 on the CPU; the compiler warns above 256 ("exceeds the M10 GPU limit"). Overflow → next context, else default material, with a warning. | fidelity + incremental (gpu-perf: hard 256) |
| K16 | **Energy LUTs** (~680 KB, float32): `ggxE` 32², `ggxEavg` 32, `ggxABC` 32²×3, `dielRT`/`dielRTinv`/`dielR` 32³, `fAvgDiel` 64, `charlieE` 32², thin-walled sheet `thinRT` (E_R' + E_T') / `thinR` (E_R') 32³. Generated offline by `tools/nova_bsdf_precompute` from the runtime sampling code (double accumulation, Owen-scrambled Sobol, TBB), committed with a generator hash. Layering albedo of a compensated dielectric R = `E_R/E_RT`. Delta when `max(αx, αy) < 1e-3`. | all three (conflicts resolved as in plan-incremental §0) |
| K17 | **Shade stage:** per bounce a stable counting sort of hits by `MaterialId`, then 32-lane chunks per material; `runLane` for groups of ≤ 2; varying-free materials skip the VM. Samples depend only on (pixel, index, stream), so sorting never changes images. | all three |
| K18 | **Light `diffuse` and `specular` multipliers** both apply: `evalClosure` returns `fcos` and its diffuse-class part; a BSDF sample carries its `diffuseShare` for the next light hit. | incremental + gpu-perf |
| K19 | **Default material** (`MaterialId 0`): Lambert(`displayColor` attribute, else 0.18), i.e. today's look, so every unbound husk/cli scene keeps its result. A single Lambert lobe draws `get3D(kBsdf).xy == get2D(kBsdf)`, so M2 images stay bit-identical. | all three (pending user confirmation, Q1) |
| K20 | **Sobol streams:** `kBsdf` 3D (xy direction, z lobe pick; the remainder `(z − cdf[j−1])/p_j` drives inner choices such as R/T); `kOpacity` 1D; `kSpare` (7) becomes `kTexture` (stochastic texture filtering, per slot `fract(u + φ·slot)`); `kLayer` stays reserved. | all three |

## 2. Scope

### 2.1 M3 delivers

- **Shading core** (`core/shading`): typed IR, optimizer (fold by running the real op, exact identities only, CSE, DCE, uniform hoisting, derivative-cone cloning, Sethi-Ullman scheduling, first-fit rows), 16-byte bytecode, batch and lane executors, ~70 opcodes, MaterialX noise bit-exact to MaterialX/Karma, own polynomial transcendentals.
- **Lobe library** (`core/bsdf`): Lambert, translucent, QON, EON, GGX conductor (n,k and F82-tint), dielectric R / T / RT and delta variants, thin-walled dielectric, Charlie sheen (MaterialX form), Zeltner fuzz, Airy thin film (grey DC term); energy LUTs.
- **Surface models:** Standard Surface 1.0.1/1.0.0 and OpenPBR 1.1.1 with every parameter except those in 2.2; `surface_unlit`; UsdPreviewSurface (Q6).
- **Integrator:** closure NEE/BSDF sampling with transmission, delta lobes and MIS sentinel (`bsdfPdf < 0` ⇒ weight 1), side-correct ray offsets, `etaScale` in Russian roulette, Beer absorption (`transmission_depth`), emission on hits, light `specular` multiplier, ray cones, path event flags (D/G/S × R/T, for M4 rayswitch and M6 LPE), closure-based albedo/normal AOVs.
- **Hydra:** `HdNovaMaterial` sprim, context chain, MaterialX expansion and Karma-semantics lowering, generic primvars (meshes, subdivision surfaces, instancers), GeomSubset slots, IPR with value edits that never recompile, `TF_DEBUG HDNOVA_MATERIAL`.
- **Textures:** OIIO TS, auto-conversion (`.rat` via `imaketx`), UDIM (`<UDIM>`, `<UVTILE>`), address modes, filters, color spaces, normal maps, bump/heighttonormal, Karma tangent frame from `st`, anisotropy rotation, missing-texture policy, statistics.
- **Opacity:** cut-out and fractional, in camera, indirect, shadow and first-hit rays.
- **Nodes:** all MaterialX 1.39.5 stdlib primitives, the matrix family included (M3.7: matrices are rows of width n, MaterialX row vectors); the pbrlib utilities with closed forms (`artistic_ior`, `blackbody`, `roughness_*`, hair absorption/roughness); legacy 1.38 `swizzle` and `atan2`; all 198 stdlib nodegraphs and Houdini's `hmtlx*`/cmlib graphs through expansion. Of the 746 definitions with a numeric output, 698 lower without a warning; the rest are textures (M3.8), the tangent frame, normal maps and bump (M3.10), `hextiled*`/`flake*` (M4) and two proposals (deviation 12).
- **Tests and tools:** chi²/furnace/albedo harness, VM differential tests and goldens, Hydra IPR driver, `husk_materials`, 8 new reference scenes, `nova_imgcmp --region`, `nova_bsdf_precompute`, CUDA compile check.

### 2.3 Deviations from PLAN.md (stated explicitly)

1. **"OpenPBR/Standard Surface komplett"** excludes dispersion, `transmission_scatter`, random-walk SSS and displacement (table 2.2): each needs infrastructure PLAN.md places later or nowhere.
2. **Karma CPU as material reference:** pattern nodes follow Karma exactly; BSDF math follows MaterialX/OpenPBR, and Karma comparisons carry documented per-region tolerances (K2). Karma's `mxpbr.h`, `ggx_utils.h` and `mxstd.h` are SideFX-proprietary and are never copied; behaviour is reproduced from MaterialX (Apache-2.0), pbrt/Cycles (Apache-2.0), EON (MIT) and black-box measurements.
3. **`kma` context in M3** although the `kma_*` mapping is M4: without it the default Solaris material builder renders nothing. Only the MaterialX content renders in M3.
4. **UsdPreviewSurface native in M3** (PLAN.md lists node mappings under M4): it is the universal fallback for every material, incl. husk's auto previews (Q6).
5. **Reciprocity** is tested per lobe only; albedo-scaling layering (MaterialX, OpenPBR, Karma) is non-reciprocal by definition.
6. **`IAccel` gains an opacity filter hook** (K10).
7. **Light `specular` multiplier** is added (K18); M2 applied only `diffuse`.
8. **Texture auto-conversion writes files** to `$HOUDINI_TEMP_DIR/nova_tx` (Q4).
9. **CUDA compile-only check** (K14) is added in M3 as tooling.
10. **Analytic spheres** (step M3.6b) are not in PLAN.md; added at the user's request (Q9), because implicit spheres from the Sphere LOP render faceted.
11. **st on analytic spheres** is not Karma's: Karma's native sphere returns its quadric's internal parameters (measured: symmetric under (x, y) -> (-x, -y), so no usable texture layout). Nova uses longitude around +Y (u = atan2(-z, x) / 2pi) and latitude from the bottom pole (v), unless the prim authors `st`. A sphere costs one Embree sphere point (16 bytes) instead of UsdImaging's 10 x 10 cage (~100 points, 180 triangles).
12. **`ambientocclusion` and `curveadjust`** (rolled back to proposals in MaterialX 1.39.2, no implementation in the libraries) lower to 1 and to their input with one warning each. Ambient occlusion needs ray queries from shading; it returns with the `kma` AO node (M4).

## 3. Architecture

### 3.1 Data flow

```
Solaris / husk / nova_cli
  UsdImaging scene index ── material sprim ──> HdNovaMaterial::Sync
     networkSource   HdMaterialSchema (terminal SI); chain nova > kma > mtlx > ""   [fallback GetMaterialResource]
     mtlxDocument    HdMaterialNetwork2 -> mx::Document(setDataLibrary) -> flattenSubgraphs(keep intrinsic + native)
     lower           mx graph -> nova::shading::IrGraph (+ texture requests, primvar names, params)
     registry        structureHash -> ProgramCache (shared Program); texture system handles; attribute ids
     Scene::updateMaterial / updateMaterialParams                (render stopped only here)
  HdNovaMesh::Sync ── attributes (all numeric primvars), material slots (+ GeomSubsets)
  Scene::commit ── material table (programs sorted together), prologues, SurfaceParams templates,
                   attribute remaps per (mesh, slot), opacity filter flags
Renderer / renderWave (per tile)
  Generate -> Intersect (opacity filter) -> Shade:
     pass A  lights / misses / escapes (as M2) + absorption + light multipliers; collect hits
     pass B  counting sort by MaterialId
     pass C  per material, 32-lane chunks: ShadingPoint -> global rows -> VM -> SurfaceParams
             -> buildSurfaceClosure -> emission, NEE (shadow queue), BSDF sample, RR, cone update
  -> Shadow (occluded, opacity filter)
```

`nova_core` stays free of USD, HDK, OIIO and MaterialX.

### 3.3 Key data structures (condensed; details in plan-incremental §2.3 and plan-gpu-perf §2.3)

```cpp
// core/shading/program.h — POD, uploadable unchanged
struct Instr { Op op /*u16*/; uint8_t width, flags; uint16_t dst, a, b, c; uint32_t imm; };   // 16 B
// flags: kUniformA/B/C, kSplatA/B/C, kExt (extension words follow), bit 7 reserved (spec semantics)
enum class Global : uint8_t { P, Pobject, N, Ng, Nobject, T, B, I, UV0, Time, Frame, RayDepth, RayType,
                              PrimId, InstanceId, Count };   // N is NOT face-forwarded (MaterialX semantics)
struct Program {   // immutable, shared by structure hash
    uint64_t structureHash;
    std::vector<Instr> code, prologue, opacityCode;   // varying; host-uniform; DCE'd to opacity (empty = opaque)
    std::vector<UniformInit> uniformInit;              // zero | const | param | hoisted
    std::vector<float> constants; std::vector<OutputBinding> outputs;   // -> SurfaceParams fields
    std::vector<TexSamplerState> samplers;             // per Tex2D slot (no path: the path lives in MaterialDesc)
    std::vector<std::string> primvars;                 // slot -> name (structural)
    uint16_t rowCount, uniformCount, paramCount; uint32_t globalMask;
    SurfaceModel model; uint32_t flags;                // kVaryingFree, kHasOpacity, kEmissive, kTransmissive, kNeedsTangents, kNeedsDerivatives
};

// core/bsdf/closure.h — built per lane at the hit, consumed at once, never stored in queues
struct Lobe {                       // ~96 B POD
    Spectrum weight; float pick;    // all layering / tint / darkening factors at wo; selection probability
    LobeType type; uint8_t flags /*delta, R, T, thinFilm, diffuseClass, coatFrame*/, fresnel, event;
    float ax, ay, etaF, etaT, energy;
    Spectrum c0, c1;                // F0|n|rho ; F82 tint|k|T tint
    float tfThicknessNm, tfIor, tfWeight;
};
struct ClosureList { static constexpr int kMaxLobes = 8; Lobe lobe[kMaxLobes]; float cdf[kMaxLobes];
                     Frame frame[2]; Vec3f ng; Spectrum emission, albedo, sigmaA;
                     uint8_t count, nonDeltaMask, flags /*hasTransmission, thinWalled, entering*/, pad; };
struct ClosureEval   { Spectrum fcos, fcosDiffuse; float pdf; };
struct ClosureSample { Vec3f wi; Spectrum weight; float pdf /*< 0: delta*/; float diffuseShare, roughness;
                       uint8_t flags, event; };

// core/scene/material.h
using MaterialId = uint32_t;        // 0 = built-in default material
struct MaterialDesc { std::shared_ptr<const shading::Program> program; std::vector<float> params;
                      std::vector<TextureId> textures; std::vector<AttributeId> attributes; };
// Scene: createMaterial, updateMaterial, updateMaterialParams (IPR fast path), removeMaterial,
//        setMeshMaterials(mesh, slots, triangleSlot) (no BLAS change), updateMeshAttributes (no BLAS),
//        setMeshInstanceAttributes, setTextureSampler(const ITextureSampler*), materialOf(mesh, prim)
```

**Attributes** replace `displayColor`/`cornerColors`/`instanceColors`: `MeshAttribute { id, rate (Constant | Uniform | Vertex | Corner), width 1–4, data }`; instance attributes per instance; lookup order mesh → innermost instance → op default (today's displayColor rule, generalized).

**ShadingPoint**: P, Ng (authored), N (interpolated, not face-forwarded), Pobject/Nobject (prototype space for instances), barycentrics, mesh/prim/instance, wo, time, uv0, dPdu/dPdv from the triangle's `st`, Karma T/B (`T = norm(dPdu − N(N·dPdu))`, `B = norm(N×T)·sign((T×dPdv)·N)`; no st → first triangle edge; degenerate → makebasis), footprint vectors; optional parts only when the program's `globalMask` needs them.

## 4. Execution model

1. **Pass A** (M2 logic): camera-visible lights, misses, escapes and area lights along BSDF rays. New: `beta *= exp(−σa·t)` for paths inside an absorbing dielectric (a miss uses `tMax`); light contributions scaled by `share·L.diffuse + (1 − share)·L.specular`; `bsdfSampleWeight` returns 1 when `bsdfPdf < 0` for every strategy (today `powerHeuristic(0, ·) = 0` would make light seen through mirrors and glass vanish). Survivors push `(ray, materialOf(mesh, prim))`.
2. **Pass B:** stable counting sort by material.
3. **Pass C**, per material group in 32-lane chunks:
   - resolve hits (only what `globalMask` needs), write global rows (incl. shifted rows), pad lanes `[n, 32)` with lane n−1;
   - VM: skipped if varying-free; `runBatch<32>` (n ≥ 17), `<16>` (9–16), `<8>` (3–8), `runLane` (n ≤ 2);
   - per lane: copy the material's `SurfaceParams` template, apply varying bindings, normalize vectors, `buildSurfaceClosure`;
   - emission: `radiance += beta·cl.emission` (MIS weight 1 until M9; indirect clamp as for escaped light);
   - last iteration (`depth == maxDepth`): stop after emission;
   - **NEE** if `nonDeltaMask != 0`: one light by power; light sampled from the offset origin on the `wi` side; a lobe returns 0 when its R/T class disagrees with `sign(dot(wi, ng))·sign(dot(wo, ng))`; contribution `beta·(e.fcosDiffuse·L.diffuse + (e.fcos − e.fcosDiffuse)·L.specular)·Li·w/lightPdf`, power heuristic against the mixture pdf;
   - **continuation:** `sampleClosure(cl, wo, get3D(bounce(d, kBsdf)))`; reject if `!(pdf > 0) || !isFinite(weight)`; origin offset to the `wi` side; `bsdfPdf = delta ? −1 : pdf`; event bits; refraction into a non-thin dielectric sets `insideMedium`/`sigmaA` and `etaScale *= η²` (out: cleared, `/η²`), entering vs exiting from the authored Ng; thin-walled never changes the medium;
   - **Russian roulette:** `survive = clamp(maxComponent(beta)·etaScale, 0.05, 0.95)` from `rrStartDepth`;
   - **ray cone:** `spread = scatterSpread(spread, W, curvature, dot(ng, d), s.roughness)` (diffuse 1, delta 0).
4. **First-hit AOVs** run the same machinery in AOV mode (center rays, sample-0 seeds, `rnd = −1` for textures): albedo = `cl.albedo` (Σ w·Ê), normal = shading normal after normal mapping, face-forwarded.
5. **Opacity** never reaches the shade stage (K10). Camera rays passing every surface are misses, so alpha follows `1 − ∏(1 − o_i)` (Karma: 0.75 for o = 0.5 on a sphere). Transmission never reduces alpha.
6. **Determinism:** sorting changes only the processing order; each path's additions keep their bounce order.

**CUDA mapping (M10):** per-bounce CUB radix sort by material, one thread per hit running `runLane` (a warp sees one material, so the switch does not diverge), rows in local memory (≤ 256), uniforms via `__ldg`, `ClosureList` in local memory, `BsdfTables` as one uploaded blob, textures through OptiX Toolkit demand loading `tex2DGrad` on the same converted EXRs, opacity in any-hit with the same hash. Details: plan-gpu-perf §2.6.

## 5. BSDF and surface-model decisions

Formulas, sources and sampling per lobe: **plan-fidelity §3.1** (lobe table) and **plan-incremental §3.1**; layering closed forms: **plan-fidelity §3.3** and `surface-models.md` §2.3 (Standard Surface) / §3.4 (OpenPBR). Binding choices:

- **GGX:** anisotropic D; stable height-correlated G2; spherical-cap VNDF (Dupuy & Benyoub 2023), bounded cap (Eto & Tokuyoshi 2023) for reflection-only lobes, full cap for anything that transmits. α clamped to [1e-4, 1]; delta when `max(αx, αy) < 1e-3`.
- **Roughness mapping:** SS `mx_roughness_anisotropy`; OpenPBR `α_t = r²√(2/(1+(1−a)²))`, `α_b = (1−a)α_t`.
- **Dielectric:** Walter 2007 with exact Fresnel per microfacet; BTDF × 1/η² (radiance transport); glass = one RT lobe with `1/E_RT` (η > 1) or `1/E_RTinv`; partial transmission or SS `transmission_extra_roughness` = R + T with the exact split.
- **Thin-walled:** Cycles thin-glass sheet Fresnel; T lobe = mirrored R lobe with `α_t = sat(α·√(3.4(η−1)(η−0.5)²/η³))`; compensated by `1/E` with `E = E_R' + E_T'` (`thinRT`). SS `specular` s < 1 scales the sheet's reflection and gives what it loses to the transmission: T' × `(E − s·E_R')/E_T'` with the sheet's own albedos (`thinR` = E_R', `E_T' = E − E_R'`, both integrated from the lobe), so the sheet keeps the energy of s = 1 at every roughness, angle and IOR (smooth sheets: R'/T' at μ, exact). Fake caustics and the albedo AOV take the smooth sheet's boost at μ (roughness ignored).
- **Conductor:** exact (n,k) with Gulbrandsen artistic IOR (SS); F82-tint clamped ≥ 0 (OpenPBR); multiple scattering `f·(1 + F_ms(1−E)/E)`, `F_ms = F_avg·E_avg/(1 − F_avg(1−E_avg))`. Tables are indexed by the rms α of the (clamped) lobe. That is close for isotropic lobes and for anisotropic ones at normal incidence up to r ≈ 0.8 (measured +3.6 % for a white metal at r 1, aspect 2.56). At grazing views the anisotropic albedo depends on the azimuth, so the white furnace holds only to ±10 %. If M3.10 needs better, the step is an azimuth-averaged E(r, aspect, μ) table.
- **Diffuse:** QON = MaterialX `mx_oren_nayar_diffuse`, uncompensated (SS; like the definition it reflects up to ~1.4 % more than it receives at grazing views); EON (Portsmouth/Kutz/Hill 2024, the paper's code) with CLTC + uniform one-sample MIS (OpenPBR).
- **Sheen/fuzz:** SS Charlie in MaterialX form + `charlieE` LUT; OpenPBR Zeltner LTC with MaterialX fits.
- **Thin film:** Airy, 2 iterations, `F = lerp(F, F_airy, weight)`, working-space matrix normalized so the DC term stays grey (no Karma R/G cast).
- **Layering:** albedo scaling at ωo with untinted E (MaterialX semantics, verified in Karma). OpenPBR coat darkening uses MaterialX/Karma `K = 1 − (1 − F0c)/η_c²`; OpenPBR thin-walled SSS per spec (not the graph's C² bug).
- **Selection:** `p_j ∝ max(lum(w_j·Ê_j(ωo)), 1e-3·Σ)` for lobes with weight > 1e-5; depends only on ωo.
- **Sides:** opaque closures are two-sided (frames face-forwarded); transmissive closures follow the authored Ng (back side: R-only layers dropped, RT lobe with 1/η and `E_RTinv`); thin-walled always front.
- **Absorption:** `σa = −ln(clamp(transmission_color, 1e-5, 1))/depth` for depth > 0 (tint 1 then); depth 0 tints at every refraction.
- **Emission** is not clamped (M3.7): negative emission colors or weights subtract, as in Karma, which unlit utility passes rely on; only non-finite values become 0.
- **Robustness:** sanitized inputs (weights [0,1], colors ≥ 0 except emission, η ∈ [1e-4, 100]); Cycles `ensure_valid_specular_reflection` per closure frame (not for the Lambert-only default closure: diffuse lobes need no valid mirror direction, as in Cycles and M2); NaN/Inf rejection; μ ≥ 1e-6 in lookups; a flat normal map is bit-identical to none.

Deliberate, measured Karma differences (each gets a region tolerance with a reason): Karma's Schlick-fit dielectric (+4.7 % at μ 1, α 0.09; −21 % of the specular part at μ 0.5), Lambert-shaped SS sheen, sRGB thin-film cast (R/G 1.27), uncompensated rough glass (−3 % at r 0.3, −34 % at r 0.7), metals at r ≥ 0.7 (−1.5…−8 %), SS QON on Karma CPU (3–5 %). Table: plan-incremental §3.7.

Notes on M3.7 as built: the procedurals (`Noise`, `Fractal`, `CellNoise`, `Worley`, HSV) run per lane in every executor (a gather/scatter around one scalar implementation), so the batch executors are bit-identical to `execute<1>` by construction. A position beyond int's range, or a NaN, has the cell INT_MIN on every device (`floorInt` through `toInt`; Worley sums its neighbour cells in 64 bits), and an infinite or NaN octave count gives no octave: what the CPU rendered before these conversions were defined (bug audit S-1, `docs/bug-audit-2026-11.md` section 9). The `mtl_nodes` probe grid is deterministic in both renderers (Nova point filter, Karma box filter at scale 1e-6) and compares per pixel (`nova_imgcmp --pixel-tol`, 32-bit reference): 24 tiles, worst pixel at 0.28 of the allowed difference. `rgbtohsv` gets saturated input colors there, because the hue is ill-conditioned near grey (an ulp of noise moves it by 1e-4).

Notes on M3.8 as built:
- **VM:** `Tex2D` (a = uv, b = footprint derivatives from M3.9 or none, c = fallback; imm = slot) is always varying and never folds. The translator gives every distinct (texture request, sampler state) its own slot. The slot states (wrap s/t, filter, channels) are structure; the files are values (`MaterialDesc::textures`, one `TextureId` per slot). The batch executor calls `ITextureSampler::sample2D` once per instruction and chunk, and per-lane status selects the fallback.
- **Host:** `hydra/textureSystem` is Nova's private `TextureSystem` on the shared `ImageCache` (`flip_t`, `gray_to_rgb`). It holds a registry of stable ids, and a request is re-prepared when its source files change, on the next material sync (file watching is M7). `hydra/textureConvert` decodes with Nova's own OCIO path (the same as light textures), then `make_texture` writes half, tiled 64, MIP-mapped EXRs. `.rat` files go through `imaketx`. A gamut-only change of a ready file is the 3×3 matrix after the lookup.
  - Deviation: cache names use a 64-bit FNV-1a of (version, color space, layer, path, size and mtime per file) instead of SHA-1. They are only names in a per-user cache.
- **Color space rules** (`hydra/colorSpace`, shared with light textures):
  - an explicit hint wins (`colorSpace` metadata on the file input, UsdUVTexture `sourceColorSpace`; float and vector image signatures are raw);
  - then 1- and 2-channel images are linear;
  - then the OCIO file rules (not the default rule), then the file metadata;
  - then png/jpg/tga/tif/tx are sRGB (imaketx writes `.tx` sRGB-encoded even as half float, measured on Karma in M2);
  - then 8-bit data is sRGB, and anything else linear.
  - `.rat` files (no OIIO reader; Houdini's HDRIs in `$HFS/houdini/pic/hdri` are `.rat`) follow the same rules, with the stored color space as their metadata: `HdNovaReadableTexture` has `imaketx` write a tiled EXR into the cache, decoded by the stored space (8-bit sRGB data linearized, tagged e.g. `lin_rec709`), or with the stored values unchanged (`-m builtin -l 0`) when a hint or a file rule decides the space (`HdNovaTextureColorSpaceIsNamed`). Light textures read them the same way; until November 2026 dome and rect lights failed to load them (plain light color), and surface `.rat` textures skipped the conversion to `scene_linear` (ACES configs) and ignored hints and file rules.
  - Measured on Karma CPU with husk (November 2026, dome lights and MaterialX images, Houdini's and the ACES cg config): float `.rat` as stored, 8-bit `.rat` decoded, `*srgb_tx*.rat` decoded and `*ACEScg*.rat` converted from the stored values, a raw hint keeps an 8-bit `.rat`'s codes; under the cg config `.rat`, EXR, HDR, `.tx` and PNG domes are converted to ACEScg; the file rules apply to light textures as to surface textures; `colorSpace` metadata on a dome's `inputs:texture:file` changes nothing in Karma (it does on a MaterialX image's `file`). Nova matches all of these on CPU and XPU (`tests/husk/check_textures.py`). Pitfall when measuring: husk applies the OCIO file rules to the output file name too (an output named `*ACEScg*` is written in ACEScg), so measurement outputs need neutral names.
- **Nodes:** MaterialX `image` and `UsdUVTexture` (scale, bias, fallback; `useMetadata` wraps black, like converted files) are native. `tiledimage`, `triplanarprojection`, `latlongimage` and the glTF images expand to them. 724 of 746 numeric definitions now lower.

Notes on M3.9 as built:
- **Ray cones:** `WaveQueues::coneWidth/coneSpread` per path. The camera cone comes once per tile from three rays one pixel apart (`cameraCone`). At a hit, `coneFootprint` turns the cone into the ellipse's footprint vectors, scaled by `nova:textureFilterWidth`. They are computed only for materials with textures, and the first-hit AOVs use them too. After scattering the width moves to the hit:
  - diffuse lobes set the spread to at least 1;
  - glossy and specular lobes add the curvature term and the lobe's alpha.
  - `Scene::curvature` (corner normals, 1/R on spheres) is computed only then.
- **Derivatives (K7):** the compiler clones the varying cone of a `Tex2D` uv twice. The clones read `PDx/PDy` and `PobjectDx/PobjectDy` and primvars shifted by a footprint vector (primvar binding `shift`, using the hit's `dudP/dvdP`). The differences feed `Tex2D.b`. The clones share all uniform work; a uniform uv gets no derivatives.
- **Stochastic filtering:** `stream::kTexture` (former `kSpare`) gives one sample per hit, decorrelated per slot. The texture system sets `stochastic = 3`.
- **Measured against Karma:**
  - MIP levels 2.00 / 4.0 / ≈0 at 16 / 64 / 4 texels per pixel;
  - a 64× minified checker averages 0.5;
  - `mtl_textured`: the grazing ground within 0.1 %, the raw map within 0.2 %. The rough OpenPBR metal is a region (Karma +4.5 % at r 0.5, up to 12 % with the map).
  - Karma filters 8-bit sRGB `.tx` files in their encoded space (−30 % on a minified high-contrast checker). Nova decodes before filtering, so the mean is exact; the reference uses a linear checker.
- **Performance:** a diffuse-only Standard Surface (Karma's default look, and the reference scenes' `displayColorLambert` since M3.6) now builds one lobe without the layer work. That is +10–13 % rays/s; numbers in docs/benchmarks.md.

Notes on M3.10 as built:
- **Tangent frame:** globals `DPdu/DPdv` come from the graph's tangent uv set (the primary uv set, `st`). The program binds that set like a primvar and reads it at the triangle corners; spheres use their surface parameters. Karma's `T = norm(dPdu - N(N.dPdu))` and `B = norm(N x T) sign((T x dPdv).N)` are IR (`tangent`, `bitangent`, `Tworld`/`Bworld` defaults). Without st the frame follows the triangle's edges; degenerate cases fall back to any basis.
- **normalmap:** Karma's formula (Gram-Schmidt T and B against N, the 1.001 Ng guard). Legacy 1.38 object-space maps go through the object's cofactor transform.
- **heighttonormal:** Karma's world-space bump. A new IR op `Deriv` expands, like the texture derivatives, into shifted clones of the height along the footprint vectors. The bumped normal is cross((fx + Ng dh_x s), (fy + Ng dh_y s)), expressed in (dPdu, dPdv projected off Ng, Ng). With `nova:textureFilterWidth 0` there are no footprints and the bump is flat. `bump` is its nodegraph. 734 of 746 numeric definitions lower; the rest are `hextiled*`, `flake*` (M4) and the two proposals.
- **Anisotropy:** the default tangent is Karma's T, bound only when an anisotropy input is connected or authored non-zero. Deviation from K6: enabling anisotropy is a structure change and recompiles once; otherwise every Standard Surface would pay for the tangent frame.
- **Diffuse lobes (changed):** Lambert lobes now see max(n.wi, 0) in their frame, which faces wo's geometric side, and sample that hemisphere, as Cycles does. Before, wo and wi had to be on the same side of a bent shading normal. That blacked out normal-mapped rims that Karma lights (`mtl_normals`).
- **Measured against Karma (`mtl_normals`):**
  - normal-mapped sphere within 0.04 %; noise-bumped ground within 0.02 %;
  - anisotropic metal with st, swapped st and specular_rotation 0.125: the same orientations, +1.5–2.5 % (Standard Surface rough metal).
- **Unit tests:**
  - flat, tilted, below-surface and swapped-st normal maps (exact);
  - h = 0.6 u bumps to norm(-0.3, 0, 1);
  - a lit tilted map gives cos α;
  - a random normal map in a white furnace gives 0.876 ≤ 1 (bent shading normals lose energy, as in Cycles).
  - Deviation from the gate's "bit-identical": a flat map equals no map to 1e-6, because normalizing a unit normal can change an ulp.

Notes on M3.11 as built:
- **Programs:** `compile` also builds `Program::opacity`, the graph reduced to its opacity outputs (opacity and opacityThreshold), without footprints. It exists only if those outputs vary per hit.
- **Material records:** `MaterialRecord` keeps the uniform opacity (`surfaceOpacity`: the mean of the opacity color, then the threshold: a threshold > 0 cuts at it) or the opacity program's uniform block.
- **Scene and filter:** `Scene` owns the opacity filter (`IHitFilter`). At every commit it marks meshes whose slots' materials have opacity (`setMeshFiltered`) and clears marks that no longer apply.
  - The filter resolves the candidate hit and runs `evaluateOpacity` (the shade stage's input evaluation for one lane, `thread_local` rows).
  - It accepts with probability o: a hash of (the ray's filter seed, mesh, prim, instance) against o, so repeated calls agree (the mesh by its stable key, not its id: docs/bug-audit-2026-11.md D-1).
- **Seeds:** `RayQueue::filterSeed` per ray comes from `stream::kOpacity` per bounce. Shadow rays shift the seed by 0.5, so they decide independently of the ray that found the surface. First-hit AOV rays use the pixel's first sample.
  - Seeds are drawn only while some mesh is filtered; opaque scenes stay at M3.9's speed (`cornell_rect` 21.8 Mrays/s, `dome_sky` 29.6, `motion_blur` 38.6).
- **Tests:**
  - an opacity-0.5 unlit sphere gives color and alpha 0.75 (3e-3);
  - a per-hit checker cut-out covers exactly;
  - a 0.5 plane halves its shadow (0.5 ± 0.01);
  - filter decisions repeat for the same rays.

Notes on M3.12 as built:
- **UsdPreviewSurface (native):** `SurfaceModel::UsdPreview` follows MaterialX's `usd_preview_surface` graph on Nova's lobes:
  - a clearcoat Schlick layer (F0 from `ior`);
  - the metalness workflow: an artistic-IOR conductor from `diffuseColor` with weight `metallic`, over a Schlick layer (F0 lerp(R² tint, tint, M)) whose base Lambert is weighted by 1 - M a second time, as in the graph;
  - the specular workflow: a Schlick layer with F0 = `specularColor`;
  - `opacityMode` transparent: the base refracts (smooth, `ior`); `opacity` with `opacityThreshold` > 0 cuts out (M3.11).
  - Schlick layers are compensated like the other dielectric layers (MaterialX's `generalized_schlick_bsdf`).
- **Measured against Karma** (`test_hydra_normals.cpp`, white dome, direct light): diffuse C = (0.5, 0.25, 0.125) against Karma's (0.5139, 0.2733, 0.1530) and the defaults against 0.2062, ± 2 %.
  - Deviation from the gate's ± 2 %: blue is +2.8 %, so its tolerance is 3 % (in husk too, `check_materials.py`). Karma's Schlick lobe lacks the multiple-scattering compensation (Karma's specular reflects S = 0.0327 of the dome, Nova's 0.0369).
  - A VEX Material Builder material renders its auto-generated preview (Nova has no `vex` context before M5): same values (`check_materials.py`, `vexpreview`).
- **References:**
  - `mtl_diffuse` puts Standard Surface's QON, OpenPBR's EON (roughness 0, 0.5, 1), UsdPreviewSurface and a default Standard Surface side by side against Karma, direct light only. Regions with reasons: SS QON r1, OpenPBR EON r0.5/r1.
  - `mtl_kma_context` holds materials authored only for `outputs:kma:surface` (the Karma Material Builder); Nova reads them like Karma.
- **Albedo probes:** `tests/reference/tools/gen_albedo_ref.py` is an independent numpy oracle. It computes microfacet albedos by stratified VNDF Monte Carlo with MaterialX's G2, diffuse albedos by split Gauss-Legendre quadrature, and Nova's chosen compensations: Turquin with Cycles' F82 estimate of F_avg for the exact conductor, the F82 curve's average by quadrature, and E_R / E_RT for dielectric layers.
  - It writes `tests/data/albedo_ref.json`: 15 probes (Lambert, QON, EON, SS and OpenPBR metals, dielectric layers) on a grid in u = (2/π) asin(√μ).
    - That grid is linear in √μ at grazing angles and in sin θ at normal incidence. On a √μ grid the rough diffuse albedos (infinite slope in μ at μ = 1) interpolated 2e-3 low.
  - `nova_tests "[albedo]"` renders each probe on an analytic sphere (orthographic, point-sampled, direct light). It compares ten μ bins per channel at 3e-3 absolute.
    - The largest bin difference is -1.3e-3 ± 2e-4 (SS metal r0.2, μ < 0.1: the 32-point tables); every other bin is within 7e-4.
- **Karma albedo probe:** `tests/reference/tools/karma_albedo_probe.py` renders the same probes with Karma CPU (a Points sphere) and writes `tests/reference/karma_albedo.json`. Re-run it on a Houdini version change, before regenerating references. Karma 22.0.466 against the oracle, disk means:
  - Lambert +0.01 %;
  - SS QON −3.1 % (r0.5) and −4.7 % (r1);
  - OpenPBR EON brighter in dark channels: +2/+5/+8 % (r0.5), +4/+10/+16 % (r1) for base (0.8, 0.5, 0.2);
  - colored SS metals brighter as roughness grows (copper green/blue +0.4 % at r0.2, +4/+5 % at r0.5, +18/+24 % at r0.8);

  - OpenPBR copper +1 % (r0.3) and +13/+17 % (r0.7);

- **Performance** (`docs/benchmarks.md`, M3 final):

## 8. Test strategy and gates

- **Principle:** exactness comes from analytic tests, furnaces and statistics; Karma comparisons verify translation and integration, never BSDF exactness.
- **Tolerance tiers:** analytic (block 0, global ≤ 5e-4); Karma-agreeing (≤ 0.02, justified by the measured Karma-vs-exact table); tolerant (per region ≤ 1.5× the measured deviation, capped at 0.10, mandatory `reason`, the remaining regions strict).
- **New reference scenes** (192×96, floating spheres from `assets/sphere_st.usda`, new `common_mtl.usda` with Karma limits 64, `causticsenable 1`, `constrainmaxrough 0`, `thinwallatrefractlimit 0`, `internalreflectenable 1`, color limits 1e9; Nova `maxDepth 64`, `clampIndirect 0`; test 64 spp, references 2 × 4096): `furnace_materials` (analytic), `mtl_diffuse`, `mtl_metal`, `mtl_glass`, `mtl_layered`, `mtl_textured`, `mtl_nodes`, `mtl_kma_context`. Contents and regions: plan-incremental §6.3. `scenes/common.usda` and `assets/sphere.usda` are never edited (their hashes guard the 14 M2 references).
- **Offline generators** (outputs committed): `nova_bsdf_precompute`, `gen_albedo_ref.py` (independent numpy oracle), `gen_vex_golden.py` (`vexexec -A 32` with `mxstd.h`, black box), `gen_node_probes.py`, `karma_albedo_probe.py`.
- **Suite growth:** about +15–25 s wall at -j4.
- **Performance gates** (this machine, label `bench`, recorded per step): untextured Standard Surface grid ≤ 1.35× the M2 Lambert wall time at equal spp; VM ~0.15–0.25 ns/(instr·lane) at N = 32; closure build ≤ 150 ns/hit; translation + compile ≤ 2 ms per material (SS + 3 textures); IPR value edit ≤ 10 ms engine side; opaque scenes unaffected by opacity support.

## 9. Risks

| Risk | Mitigation |
|---|---|
| Integrator surgery breaks M2 behaviour | default material reproduces M2 sampling bit-exactly; full M2 suite; targeted delta-MIS/IOR-1/mirror/glass tests in M3.4 |
| Subtle BSDF math bugs | validated chi² harness and two independent numeric anchors before integration |
| MaterialX library differences between husk and nova_cli | spike S1; explicit search-path order; tested in both |
| Embree argument filters and instance arrays | spike S2; geometry-filter fallback |
| Hydra 2 quirks (AllDirty edits, no mesh re-sync, empty primvar lists) | scene-index reader, own diffing, all primvars uploaded, IPR driver test |
| Shade-stage cost at deep bounces (small groups) | adaptive N, lane executor for n ≤ 2, varying-free fast path; 64×64 tiles if needed |
| MSVC does not vectorize libm/`std::fmin` | ternary min/max, own polynomials, AVX2 noise, `/Qvec-report:2` check of `vm_batch.cpp` |
| Memory from storing all primvars | measured in M3.5; union filtering in M7 |
| Register pressure of expanded graphs (`ND_ramp` has 270 primitives) | fold/CSE/DCE, row caps, failure → default + warning; counted over all stdlib graphs in M3.7 |
| Karma differences make references fragile | tiers, reasoned regions, `karma_albedo_probe.py` on version changes |
| Texture conversion races and disk use | content-hashed names, temp + atomic rename, `nova:textureAutoTx 0`, stats |

Technical questions resolved inside the steps: frame/fps tokens under husk (M3.7); USD encoding of `mtlximage` `filecolorspace` (M3.8, own Houdini instance); whether Karma converts `colorSpace` metadata on non-file color inputs (M3.7 probe tile); thread safety of `flattenSubgraphs` on a shared data library (before M7).
