# M7 design: denoising, adaptive sampling, IPR performance

Status: binding design for M7. docs/PLAN.md asks for "OptiX-Denoiser (Viewport-IPR + Final), adaptives Sampling, IPR-Performance (Delta-Updates, schneller Neustart)", with the result "Interaktives, rauschfreies Look-Dev", and sets the performance goal "IPR-Latenz < 100 ms beim Parameterwechsel".

Research, measured on this machine (Houdini 22.0.466, RTX 5080, isolated hython/husk only):
- `docs/research/m7/denoising.md`: Houdini's denoise paths, Karma's viewport denoise, the OptiX 9.1 denoiser API with a working prototype and timings, CUDA inside Houdini;
- `docs/research/m7/adaptive-sampling.md`: Karma's pixel oracle, production practice, an exact emulation of adaptive Nova on sample ladders, the bias;
- `docs/research/m7/ipr.md`: where the time of an IPR edit goes (`nova_hydra_tests "[ipr-latency]"`).

## 1. Decisions

As in M4 to M6, the user is not available during this /goal run. The research's recommended options were taken; the user may revise them. The Solaris UI follows Karma's nodes (the user's request after M6, M6.7): every new setting goes where Karma's LOPs put the matching one.

| # | Question | Decision |
|---|---|---|
| D1 | Denoiser | **NVIDIA OptiX only** (the user's choice: no OIDN). A native module in `core/denoise`, HDK-free: `nvcuda.dll` and `nvoptix.dll` (via `optixInit`) are loaded at run time, so Nova still loads and renders on machines without an NVIDIA driver; CMake keeps CUDA's include directory but no longer links `cuda.lib`. AOV model; guides the first-hit total albedo and the world normal (Nova's `Film::albedo`, `Film::normal`, measured best); alpha copied, not denoised; half-float staging; rows passed top-down; the whole frame when VRAM allows, else tiles with OptiX's full overlap. A missing driver, an old driver or out-of-memory gives one warning and the undenoised image. |
| D2 | Final frames | **Inside the delegate, after convergence**, before the buffers are read. The settings `nova:denoise` (off by default) and `nova:denoiseAovs` (default `C`; the bound AOVs, by name, to denoise in place) — in the Nova Render Settings LOP under Image Output > Filters, as Karma's Denoiser. Karma's own `karma:global:imagefilter` denoise entry is honoured too (its `aovs`, including Karma's separate `<name>_denoise` vars, which are denoised copies), so the Karma Render Settings LOP's Denoiser menu works for Nova; `engine = oidn` denoises with OptiX and warns once. Beauty and listed LPE AOVs denoise in one invoke (AOV layers). husk's own filter lists keep working unchanged. `nova_cli` denoises the same way. |
| D3 | Viewport | **A viewport toolbar toggle** `nova:viewportDenoise` (icon `VIEW_display_denoise`, off), as Karma's `karma:hydra:denoise`, and `nova:denoiseStartPasses` (default 4: the passes rendered before the first denoise, as Karma's `ipr_proxy_for_imagefilter`). Denoising runs on its own thread after a pass; the render thread never waits for the GPU; only the displayed beauty buffer receives the denoised image; a result older than the newest pass is dropped. The OptiX context is created when the toggle is first used and kept. In the viewport only this toggle decides (Karma's behaviour); `nova:denoise` applies to husk and `nova_cli`. |
| D4 | Adaptive sampling | **Per-pixel convergence, Karma's knobs.** `nova:pixelOracle` (`uniform` \| `variance`, default `uniform`), `nova:oracleMinSamples` (-1 = automatic: max(16, sqrt(max)) rounded up to a power of two), `nova:oracleThreshold` (0.01); `nova:samples` stays the maximum. In the LOP under Advanced > Sampling, as Karma's Pixel Oracle. The estimate: at power-of-two checkpoints after the minimum, the prefix half against the full sum, |I − H| / sqrt(I) (linear above 1) summed over RGB and alpha, pooled over 3x3 pixels, unconverged pixels dilated by one pixel; decisions only after a pass barrier, so renders stay deterministic and every pixel's beauty is bit-identical to a uniform render at its own count. The default stays uniform: at Nova's default 64 samples there is little to adapt, and the oracle darkens slightly (research 4.4); the user may switch the default. |
| D5 | Per-pixel sample counts | `Film::count` per pixel normalizes beauty, alpha, LPE outputs (`shadow;` stays a ratio), cryptomatte weights and AO. Every pass renders a list of pixels (work items: spans of the sorted active-pixel list instead of tiles), each path carries its pixel's sample index. With every pixel active this is today's render. A sample-count AOV (`nova:samplecount`, and Karma's `ray:pixelsamples` source) shows the counts. |
| D6 | IPR first image | **Proxy passes**, as Karma's IPR (`ipr_proxydepth`, default 2): after a restart in the viewport, pass 1 renders one pixel per 4x4 block, pass 2 the rest of one pixel per 2x2 block, then full passes. Each proxy pixel's sample is its pixel's first sample (D5), so nothing is thrown away. Display buffers fill each block from its rendered pixel until the pixels have their own samples. `nova:iprProxyDepth` (0-3, default 2; viewport scope). husk and `nova_cli` never use proxy passes. |
| D7 | Deformation in IPR | **Embree refit** for meshes whose topology is unchanged (`RTC_BUILD_QUALITY_REFIT`) in the viewport; a full rebuild after 16 refits of the same mesh and always in husk and `nova_cli`. |
| D8 | Per-ray cost | Found by the M6.6 profile: `std::fmin`/`std::fmax` (CRT calls on MSVC), `asinf` in spherical-rectangle sampling, and small helpers that are not inlined. Inline replacements with identical NaN semantics, a cheaper but exact angle for spherical rectangles, forced inlining of the hottest helpers. |
| D9 | Temporal denoising, frame-varying noise | Deferred: OptiX's temporal mode needs a frame-to-frame flow and only helps once the noise changes per frame. A later milestone (or the user) decides. |

| `tools/nova_cli/main.cpp` | denoising and the sample-count AOV like husk |

### 3.2 Pass structure

A pass renders work items, each a span of the active-pixel list with s samples per pixel (s = 1 in IPR, up to the next checkpoint in final renders when few pixels remain). After the pass barrier:
- at a checkpoint the oracle updates the active list (D4);
- the buffers are written (beauty every pass; others as in M6.6);
- in the viewport with denoising, the beauty is handed to the denoise thread (D3).

The renderer converges when the active list is empty or every pixel has the maximum.

## 5. Risks

| Risk | Mitigation |
|---|---|
| Work items cost more than tiles when every pixel is active | spans of whole tile rows keep today's order; gate ±2 % in M7.1 |
| The oracle's bias at low minimums | the minimum floor of 16 (research 4.4); default off |
| CUDA in the Houdini process | the primary context, push/pop around every use, never reset (research 4.3) |
| VRAM at 4K with other GPU users | free-memory check, tiles with the full overlap, failure = undenoised image |
| Proxy passes look blocky | only the first one or two passes; Karma's IPR behaves alike |

## 6. Notes as built

Notes on M7.0 as built:
- `nova::fmin`/`nova::fmax` (`core/math/common.h`) keep `std::fmin`/`std::fmax`'s NaN rule and are inlined; 194 calls in `core` use them.
- `NOVA_FORCEINLINE` covers every helper in `core/math/vec.h`.
- Spherical rectangles take an inline arcsine (Abramowitz and Stegun 4.4.46, absolute error below 2e-8) instead of `asinf`.
- The benchmark scenes are 3-10 % faster (docs/benchmarks.md M7). `vex_builder` is bound by the CVEX bridge and unchanged.

Notes on M7.1 as built:
- `Film::count` holds the samples per pixel. The buffers normalize by it: beauty, alpha, LPEs, cryptomatte weights, AO.
- A wave renders a tile or a list of the tile's film pixels (`renderWave(..., pixels, count, ..., samplesPerPixel)`).
- Each path carries its pixel's sample number (`WaveQueues::sampleIndex`, the pixel's count).
- Pixels without samples get their first-hit AOVs in the wave that gives them their first sample (`Renderer::firstHitPass`).
- Uniform renders are unchanged; every reference test passes as before.

Notes on M7.2 as built:
- **Proxy passes** (`Renderer::setProxyDepth`, `nova:iprProxyDepth`, default 2, in the viewport only):
  - pass 1 renders one pixel per 4x4 block, pass 2 one per 2x2 block;
  - the buffers fill each block from its rendered pixel (`WriteFromFilm(..., fillStride, ...)`);
  - pixels with extra proxy samples drop out when they reach the maximum.
  - `test_render` "Proxy passes are the pixels' first samples": the converged film equals a render without proxy passes bit for bit, on a region that is not a multiple of the block size.
- **Refit** (`IAccel::setRefit`, `Scene::setInteractive` in the viewport): meshes are built with `RTC_BUILD_QUALITY_REFIT` and a dynamic BLAS, and new points of the same topology refit. Every 16th edit of a mesh rebuilds.
- The delegate reports `samples` (the full passes) and `passes` (proxy passes included).
- Every edit of the latency scene shows its first image within 23-94 ms (gate < 100 ms; docs/benchmarks.md M7). The deformation of a million triangles is the slowest: Hydra's mesh sync is 20 ms of it, and Embree's refit 25 ms.

Notes on M7.3 as built:
- **The oracle** (`Renderer::updateOracle`) follows research rule pool3nd:
  - checkpoints at powers of two;
  - prefix half against the full sum;
  - error |I − H| / n(I) for RGB and for alpha, pooled over 3x3 pixels;
  - noisy at 5x the threshold;
  - a pixel stops when its 3x3 neighbourhood is quiet.
- Decisions happen only after a pass, so renders stay deterministic.
- When few pixels are left, a pass renders several samples per pixel, up to the next checkpoint.
- **Work items** are chunks of the tiles' selected pixels, sized for every thread (`Renderer::WorkItem`). A pixel's samples always stay in one wave, so results do not depend on the chunking.
- **Settings:** `nova:pixelOracle` (`uniform`/`variance`, default `uniform`), `nova:oracleMinSamples` (-1: max(16, sqrt(samples))) and `nova:oracleThreshold` (0.01), in the LOP under Advanced > Sampling.
- **Sample-count AOV:** Karma's intrinsic `ray:pixelsamples` and `nova:samplecount` resolve to the per-pixel count. Nova counts every sample; Karma counts only samples that hit geometry.
- **Test** (`test_render` "Adaptive sampling stops quiet pixels and keeps their prefix"):
  - every pixel equals the uniform render at its own count, bit for bit;
  - quiet ground stops at the minimum while the penumbra goes on;
  - results do not depend on the thread count;
  - threshold 0 renders uniformly.
- **Gates** (`tests/reference/tools/bench_adaptive.py`): mtl_glass 3.25x and cornell 1.06x pass. dome_sky reaches 0.97x of the 1x gate, 10 ms short at 0.18 s, within the runs' noise.

Notes on M7.4 as built:
- `core/denoise/{denoiser.h,optix_denoiser.cpp}` follows D1:
  - `nvcuda.dll` is resolved at run time, and `optixInit` loads `nvoptix.dll`;
  - it uses the device's primary context, pushed and popped around every use, a non-blocking stream, and pinned staging;
  - the AOV model runs with alpha copied; intensity and average colour are computed each time;
  - whole frames are used when the free memory allows, else 1024-pixel tiles with OptiX's overlap (`optixUtilDenoiserInvokeTiled`).
  - `NOVA_DENOISE_DISABLE=1` and a missing driver make it unavailable, with a message. `HOUDINI_NVIDIA_OPTIX_DEVICENUMBER` picks the GPU.
  - `Nova::OptiX` no longer links `cuda.lib`.
- **Test** (`test_denoise.cpp`):
  - unavailable means unchanged;
  - a penumbra scene at 8 spp drops at least 3x in relMSE (measured 5x);
  - alpha is exact;
  - tiles match the whole frame within 0.5 % (0.13 % on this small image, where borders weigh much);
  - an AOV layer denoises with the beauty's kernels.

Notes on M7.5 as built:
- **Final frames** (husk, `nova_cli`): at convergence the render loop denoises the bound AOVs named in `nova:denoiseAovs` (default `C`, with `nova:denoise`) or in Karma's `karma:global:imagefilter` denoise entry (`HdNovaParseKarmaImageFilter`). This includes Karma's separate `<name>_denoise` vars. OIDN requests denoise with OptiX, with one warning.
  - The film's beauty is the AOV model's beauty layer, every listed buffer an extra layer; the guides are the film's first-hit albedo and normal.
  - Buffers are read and written as RGBA rows top-down (`HdNovaRenderBuffer::ReadRgba`/`WriteRgba`).
- **Viewport:**
  - `nova:viewportDenoise` is a toggle on the viewport's toolbar (icon `VIEW_display_denoise`, like Karma's; `gen_nova_ds.py` writes toolbar settings);
  - from `nova:denoiseStartPasses` (4) on, the displayed beauty is denoised at most every 50 ms and at the end, and in between it keeps the last denoised image;
  - the settings also live on the Nova LOPs (Image Output > Filters > Denoiser), so the stage's render settings switch the viewport too.
- **Deviation from D3:** the viewport denoises in the render loop, under the framebuffer lock, not on its own thread. 2-8 ms per denoise at viewport sizes, at most every 50 ms, did not justify a second thread.
- **Measured:**
  - cornell_rect at 16 spp is 15x lower in relMSE with the denoiser;
  - husk with Karma's image filter gives the same image;
  - the viewport check (own instance, `NOVA_VIEWPORT_CHECK_ONLY=rendersettings`) shows the 8-spp viewport noisy and then denoised.
