# M5 design: VEX materials and the CVEX bridge

Status: binding design for M5 (docs/PLAN.md: "CVEX-Bridge für VEX-Fallback (batched, thread-local Kontexte)", result
"VEX-Material-Builder-Materialien rendern"). Research, measurements and the spike: `docs/research/m5/vex-materials.md`
(scripts in `docs/research/m5/prototypes/`). This document condenses it.

## 1. Decisions

As in M4, the user is not available during this /goal run; the recommended options were taken (**goal**) and the user
may revise them.

| # | Question | Decision |
|---|---|---|
| D1 | Render-context order | `nova` > `kma` > `mtlx` > **`vex`** > universal (Karma's order). A VEX material without a `vex` network keeps rendering its preview. |
| D2 | Shader identity | `info:id`; for `sourceAsset` shaders the asset path (universal, `VEX:` or `vex:` namespace); for `sourceCode` shaders the code. Houdini writes the universal attributes; the tests are fixed to match. |
| D3 | Principled Shader 2.0 (`opdef:/Vop/principledshader::2.0?SurfaceVexCode`, `...?DisplacementVexCode`) | **Native**: a parameter table maps it onto Nova's Standard Surface network (textures, bump/normal maps, emission, opacity, displacement) through the existing MaterialX translator (goal). PLAN.md routes known Houdini VOPs through a mapping table. This is exact for textures (VEX library helpers read `s`/`t` globals that CVEX cannot provide, research 0.6), fast, and GPU-ready. |
| D4 | VEX Material Builder code (`sourceCode`) and other VEX shaders | **CVEX bridge** (`houdini/cvex_bridge`): the surface function is rewritten into a `cvex` function (globals as parameters, Nova's inputs added, `eval_bsdf`/`sample_bsdf`/`albedo` appended), compiled at run time with VCC, run per material batch with thread-local contexts. The BSDF stays in VEX; Nova sees per-lane results (D6). |
| D5 | Shading-only VEX in the bridge | A fixed shim table (research 0.4): constants for `getraylevel`/`isshadowray`/`rayimport`, a two-argument `frontface`, removal of `pbrlighting` (AOV exports), stand-ins for `dPds`/`dPdt`/`Ng`/`isshadingRHS`/`objectstate` inside library functions, `init_layer`'s two global reads rewritten in memory. Remaining "undefined variable" errors **inside library functions** are patched to defaults from vcc's error positions (bounded loop). Errors in the shader body itself, or calls to `trace`/`gather`/`illuminance`, fail the shader: warning once, the material's preview renders (Karma XPU's behaviour). |
| D6 | BSDF conventions (measured) | f·cos θ = `eval_bsdf` / 2π (light samples). The continuation is `sample_bsdf`'s direction with **its own weight** (the sampled component's throughput, unbiased by construction). The mixture pdf = `eval_bsdf`'s pdf / (2π · A) with A = luminance(`albedo(F)`) is used **only in MIS weights**, the same function for the light sample and for the continuation, so an inexact A changes variance, not the expectation. Verified by furnace and χ² tests on known VEX lobes (M5.3). |
| D7 | Integration in the integrator | An **External lobe**: pass C runs the bridge once per material batch before shading, with the light sample `shadeHit` will draw (the sampler streams are deterministic). The lobe returns the precomputed light evaluation and the precomputed sample. Limits, Russian roulette, ray cones and MIS are unchanged. The event class comes from `sample_bsdf`'s bounce type. |
| D8 | VEX displacement | Principled: native (D3). Builder `displace` code: through the bridge (`P`, `N` in, `P` out; the offset enters M4's dicing like a displacement program). |
| D9 | Opacity of bridge materials | `Of` from the same run at camera and indirect hits. Shadow rays and the opacity filter run the bridge for single lanes, but only when `probeOutput(Of)` is not the constant 1. Otherwise the material is opaque at no cost. |
| D10 | Primvars and textures in the bridge | VEX parameters bind to same-named primvars (Mantra/Karma convention: `Cd`, `uv`, `st`, `N`, ...), and `UsdPrimvarReader` connections into VEX inputs bind their `varname`. `texture()` inside VEX uses Houdini's texture system (no ray-cone footprints; documented). |
| D11 | Hosts | The bridge runs where Houdini's VEX runtime is loaded: husk, Houdini, hython. In other hosts (`nova_cli` if VCC cannot initialize there) bridge materials fall back to their preview with one warning. |
| D12 | GPU (M10) | Bridge materials render their preview (Karma XPU's behaviour); the Principled Shader stays native. |
| D13 | Fake caustics through bridge materials | Not supported: they are opaque to fake-caustic shadow rays (no transmittance from VEX; documented). |

## 2. Scope

### 2.1 M5 delivers

- The `vex` context and VEX shader identity (D1, D2), with a warning for VEX shaders Nova cannot run, and fixed tests
  (`check_materials.py` writes the universal `info:sourceAsset`).
- **Principled Shader 2.0** surface and displacement, native:
  - base colour, metallic, roughness, anisotropy, IOR, reflectivity, reflect tint, coat, sheen, transmission, emission, opacity;
  - their textures (`*_useTexture`, wrap, colour space, mono channel, the UV transform);
  - base/coat bump and normal maps;
  - SSS as Nova's Standard Surface does (until M9);
  - texture and noise displacement.
- **The CVEX bridge** for VEX Material Builder materials and other VEX surface/displacement code:
  - transformation, shims and VCC compile with a per-code cache;
  - thread-local contexts and batched runs;
  - the External lobe, opacity, emission (a surface's global `Ce`), primvar binding, displacement.
- **References:**
  - `vex_principled` (Karma CPU);
  - `vex_builder` (Karma CPU), a builder with a Principled Shader Core, a noise pattern, a texture and displacement.
- The Solaris check gets a Principled Shader and a VEX builder material, assigned live.
- Benchmarks.

### 2.2 Deferred

| Item | Goes to | M5 behaviour |
|---|---|---|
| Classic Shader, Pyro (volume), other VEX shader HDAs natively | later / M8 | Classic and others through the bridge (D4); Pyro is a volume shader (M8) |
| VEX AOV exports (`export_*`, `direct`/`indirect`) | M6 | not exported |
| `trace`, `gather`, `illuminance`, ray-tracing VEX in shaders | — | shader fails to compile, preview renders (D5) |
| Ray-cone filtering of textures read inside VEX | — | Houdini's texture system's own filtering |
| Fake caustics through bridge materials | later | opaque (D13) |
| Light, lens, fog and volume VEX shaders | M8/later | ignored with a warning |

### 2.3 Deviations from PLAN.md (stated explicitly)

1. **The Principled Shader does not go through CVEX** (PLAN.md: unknown VEX → `CvexNode`). It is a known Houdini VOP and gets the mapping table PLAN.md describes for such VOPs. CVEX cannot run it exactly: its library helpers read shading globals (research 0.6).
2. **The CVEX node is a whole-shader External lobe, not a pattern node inside Nova's IR** (PLAN.md: "VEX-Teilgraphen ... als Fallback-Shader-Node").
   - USD carries a VEX material as one compiled function, not as a node graph. Snippets and custom VOPs are code inside it.
   - Karma's MaterialX networks cannot contain VEX nodes.
   - The BSDF stays in VEX (D6), because a VEX `bsdf` cannot cross the CVEX API.

## 3. Architecture

### 3.1 Files

```
core/shading/external.h          IExternalShading (interface, no Houdini dependency), ExternalLane, ExternalResult
core/bsdf/closure.h              LobeType::External (precomputed light eval + sample, D7)
core/integrator/wavefront.cpp    pass C: bridge pre-pass per material batch, External lobe in shadeHit
core/scene/scene.h               MaterialRecord::external (bridge shader handle), opacity flag (D9)
houdini/cvex_bridge/             HDK library (Houdini::CVEX, VEX, VCC, UT):
  transform.{h,cpp}              surface/displace VFL -> cvex VFL (shims, globals, tail), vcc error-driven patching
  bridge.{h,cpp}                 compile cache (hash of code), CVEX_Function per shader, thread-local contexts, run()
hydra/material/vexShaders.{h,cpp} VEX shader identity, Principled table (D3), bridge material creation (D4)
```

`hdNova` links the bridge. The core keeps no HDK dependency: it sees `IExternalShading` only, like `IShadingQueries` (M4.4).

### 3.2 The bridge run (D4, D6, D7)

1. **Inputs, per lane** (varying):
   - `P`, `I` (ray direction), `N` and `Ng` (authored orientation), `s`, `t`, `dPds`, `dPdt`, `Time`, `Eye`;
   - the bound primvars (D10);
   - `nova_wi`: the light direction `shadeHit` will draw, or zero when it draws none;
   - `nova_sx`, `nova_sy`: the BSDF sample numbers of `stream::kBsdf`.
2. **Inputs, uniform:** the material's parameter values (USD inputs, else the VFL defaults).
3. **Outputs:**
   - `nova_light` (eval_bsdf at `nova_wi`, and its pdf);
   - `nova_dir`, the sampled direction, with `sample_bsdf`'s weight and `eval_bsdf`'s pdf there (for MIS);
   - the bounce type;
   - `albedo(F)`;
   - `Of`, and `Ce` where the surface sets it.
4. **Conversion** (D6): f·cos = eval / 2π; MIS pdf = pdf_vex / (2π · luminance(albedo)); continuation weight =
   `sample_bsdf`'s eval as is.
5. **Event class:** from the bounce type (diffuse/reflect/refract/sss/volume masks).
6. **Batching:** a material's run in pass C, in batches of up to 256 lanes, before the 32-lane shading chunks.

### 3.3 Principled table (D3)

The translator rewrites the Principled shader's inputs into a MaterialX Standard Surface network and lets the existing
translator compile it. Textures become `ND_image_*` with the Principled wrap and colour-space rules, multiplied with the
parameter as the Principled shader does. The exact mapping (reflectivity → specular, `reflecttint`, `albedomult`,
`transparency`/`transdist`, emission intensity, opacity colour) is taken from the Principled VFL's behaviour in M5.1 and
documented there with measured differences to Karma.

Each step builds, passes the full `ctest`, leaves the renderer working and adds its own tests.

## 5. Risks

| Risk | Mitigation |
|---|---|
| A Houdini update changes the VOP library so the shims no longer suffice | the error-driven patch loop handles new global reads in library functions; M5.2's compile test of stock builder code catches the rest; failures fall back to the preview, never crash |
| CVEX/VCC not thread-safe for loading | loads under one mutex; runs on thread-local contexts only |
| The bridge is slow (VEX per lane, Houdini textures) | batches of 256 per material; measured; the Principled Shader, the common case, is native |
| The mixture-pdf normalization (D6) is off for some lobes | it enters only the MIS weights (same function on both sides), so the image stays unbiased; χ² and furnace tests on mixtures measure it |
| The Principled table differs from Karma's VEX result | references with documented regions; the bridge can evaluate a Principled Core inside a builder as an oracle for single lobes |

## 6. Notes as built

Notes on M5.0 as built:
- **What Hydra delivers** (probed with `nova_cli` and `TF_DEBUG=HDNOVA_MATERIAL`, which now prints the node type info): VEX shaders keep an **empty node type id**. Their identity is in `nodeTypeInfo`:
  - `implementationSource`;
  - `sourceAsset` (an `SdfAssetPath`) or `sourceCode` (a string), under `VEX:`/`vex:` when authored with a source type;
  - an empty `sdrMetadata`.
- `hydra/material/vexShaders.{h,cpp}`: `HdNovaVexShaderOf` classifies a node's type info into Principled surface, Principled displacement, source code, or another asset. The universal key comes first, then any `<type>:` key.
- `vex` is in the context list after `mtlx` (D1). A VEX shader Nova does not run warns once, and the next context renders: the universal preview, else the default material.
- `HdNovaMaterialRegistry::Warned` lets tests query logged warnings.
- `tests/husk/check_materials.py` writes the universal `info:sourceAsset`, as Houdini does.
- Tests: `test_hydra_vex.cpp` (identity over all namespaces; the fallback through a render index).

Notes on M5.1 as built:
- **The rewrite** (`hydra/material/principled.{h,cpp}`, D3, 3.3):
  - The Principled Shader's USD inputs become a MaterialX network around `ND_standard_surface_surfaceshader`, which the translator lowers unchanged.
  - Constant values fold in C++, and every input is always set, so value edits never recompile. The exception is anisotropy from zero, which adds the tangent frame as for any Standard Surface.
  - The rules were read from the shader's VFL and `bsdf.h` (behaviour only):
    - **Texturable values:** value · lerp(1, tex, clamp(I, 0, 1)) · clamp(I, 1, 1000). Floats read a channel: 0 is VEX's NTSC luminance, 1-3 are r, g, b.
    - **Base colour** × `Cd`, else `displayColor` (Use Point Color is on by default); × `albedomult`.
    - **UVs:** `uv`, else `st`, through the inverse of `uvtrans`/`uvrot`/`uvscale`. Wrap modes: repeat → periodic, streak → clamp, decal → black border. Colour space "linear" → raw.
    - **Reflectivity** scales only the facing reflectance (grazing stays 1): an effective IOR where nothing refracts, a specular weight otherwise.
    - **Tints** (reflect tint, sheen tint) blend towards base / luminance(base).
    - **Diffuse roughness** = the specular roughness.
    - **Anisotropy:** 0.9 |aniso| (Principled aspect √(1 − 0.9 a), Standard Surface √(1 − a)). Rotation −anisodir / 2 turns; VEX turns the other way, measured on the reference. Negative values add a quarter turn.
    - **Metal:** Schlick from the base colour to white.
    - **Sheen:** Disney's (1 − |l·h|)⁵. In Houdini's `principleddiffuse` lobe it is `FH · π` inside VEX's 2π-scaled eval, × 2.
    - **Coat:** Disney's clearcoat: IOR 1.5 with 0.25 · coat of the facing reflectance, roughness 0.1 + 0.45 coatrough.
    - **SSS:** albedo = base colour, mean free path = ssscolor · sssdist.
    - **Emission:** `emitint` × `emitcolor`. Opacity: `opac` × `opaccolor` × `Alpha`/`displayOpacity`.
    - **Normals:** base and coat bump (`(tex − 0.5) · scale`, `ND_bump_vector3`) or normal maps (flips by 1 − x).
    - **Displacement:** the texture's (value + offset) · scale along N or as a tangent-space vector, plus the `disp` input. Noise displacement warns.
- **Core additions:**
  - Primvar names may list alternatives (`"Cd|displayColor"`). `MeshDesc::findAttribute` and the scene's binder take the first one the mesh has; the binding is decided per mesh at no shading cost. Displacement found the plain names only before this fix, which left the texture coordinates at (0, 0).
  - `LobeType::DisneySheen` (`core/bsdf/sheen.h`): cosine sampled, albedo table from my own quadrature (≤ 0.088).
  - Standard Surface's `houdiniPrincipled` field selects the Disney sheen and the Schlick metal (`pushSchlickLayer`). The rewrite requests it with the internal SS parameter `nova:houdiniPrincipled`.
  - `HdNovaNetworkSource::tangentUv` lets a rewritten network name its tangent uv set (Principled: `uv|st`).
- **Reference `vex_principled`** (Karma CPU renders the real VEX shader; 8 spheres in direct light):
  - plastic +0.7 %, tinted half reflectivity +1.3 %, metal +0.7..1.4 %, sheen +2 %, displacement +2 %, coat +1.6..3.6 %;
  - regions with reasons:
    - anisotropic metal +6..8 % (Nova's GGX multiple-scattering compensation);
    - roughness-mapped sphere +3..6 % (QON vs VEX Oren-Nayar at roughness 0.95);
    - coat, sheen, displacement.
  - Before the fixes: sheen +215 % (Charlie), coat +21 %, metal B +13 % (artistic IOR), anisotropy mirrored.
  - The anisotropic sphere carries Houdini's `uv` primvar. Without it, Karma's Principled tangents follow the polygons' parametric s, t; Nova's follow `st`.
- `husk_materials`: a Principled material on a quad renders (0.8112, 0.1255, 0.1255), Karma (0.8113, 0.1253, 0.1253).
- **Deviations:**
  - Packed colour, the `vdisp` input, noise displacement, dispersion, rounded edges and the alpha cutoff mode are not supported (warnings).
  - `opdef:` texture paths, such as the textures embedded in HDAs, are not readable by Nova's texture system.
  - Principled anisotropy on meshes without `uv` differs from Karma's (see above).

Notes on M5.2 as built:
- **Interface** (`core/shading/external.h`, no Houdini types): `ExternalBridge::compileSurface(code)` returns an `ExternalShader`.
  - The shader lists its parameters: name, width, int flag, defaults; strings are uniform.
  - `run(count ≤ 256, lanes, inputs, strings, results)`. Lanes carry P, I, N, Ng, dPds, dPdt, s, t, time, the light direction and the two sample numbers.
  - Results carry the light's f·cos and MIS pdf; the continuation's direction, weight and MIS pdf; the bounce bits; albedo and opacity.
  - `bounces()` gives VEX's bounce bits per class, the label's mask together with its `all<type>` mask (`allreflect` is 32768, not a superset of `reflect`; reflect also takes `coat`), since M5.4.
- **The rewrite** (`houdini/cvex_bridge/transform.{h,cpp}`, a static library without the HDK):
  - the shim set of D5;
  - surface globals declared only where the shader has no parameter of that name;
  - shaderlayer.h inlined with `init_layer`'s two reads replaced;
  - `pbrlighting` statements and their import removed;
  - stand-ins (Ng, I, Eye, s, t, Time; never P or N, which are ShaderLayer fields) for library code, added when vcc reports them undefined;
  - parameters parsed with their default texts (string defaults are not available from CVEX).
- **The DLL** (`houdini/cvex_bridge/bridge.cpp`, `nova_cvex.dll`):
  - Built with the `Houdini` target's flags and defines, linking only CVEX, VEX, VCC, UT, SYS and TBB. The headers' implicit `tbb12.lib` needs `Nova::TBB`.
  - Compiles with `VCC_Utils::preloadLocalFunction`, at most 4 attempts as stand-ins are added; a code-keyed cache of weak pointers.
  - Loading happens under one mutex. Every thread gets its own `CVEX_ContextT<VEX_32>` and run data per shader.
  - Every float parameter is bound varying, so one load serves all materials of the code.
  - **Measured conventions** (VEX diffuse against closed forms):
    - f·cos = eval / 2π;
    - MIS pdf = pdf / (2π · A), where A is the **NTSC** luminance of `albedo(F)` (VEX's `luminance()`; Rec.709 was 5 % off);
    - the sample weight is `sample_bsdf`'s eval.
  - It is staged and installed next to `hdNova.dll` in `dso/usd_plugins`.
- **Hosts (D11):** CVEX and VCC run in a plain process (the test executable) with `$HFS/bin` on PATH, so `nova_cli` can host the bridge as well. Loading Houdini's libraries prints onnxruntime version notices on stderr.
- **Fix found by the tests:** an empty `UT_String` has no buffer; error texts from it are guarded.
- **Tests** (`nova_cvex_tests`, label `cvex`, 88 assertions):
  - the rewrite (parameters, globals not doubled, shims, stand-in placement);
  - loading, compiling and caching; a broken shader fails with a message;
  - VEX diffuse conventions per lane; uniform and per-lane parameters;
  - 8 threads × 200 runs × 256 lanes;
  - builder-style code (`tests/data/vex_builder_like.vfl`, my own code using Houdini's VOP/layer includes, `init_layer`, `vop_computeTangents`, two-argument `frontface`, `get_bsdf("ggx")`, `getraylevel`) runs through the shims.
- **Deviation from the gate:** Houdini-generated builder code is not committed (it inlines SideFX's VOP code). Its compile check runs in M5.4 through hython, which generates it.

Notes on M5.3 as built:
- **Core:**
  - `SurfaceModel::External` (no lobes).
  - `ClosureList::external` (`ExternalClosure`): `evalClosure` returns the bridge's f·cos and MIS pdf only for the light direction it evaluated. VEX's eval has no diffuse/specular split, so all of it takes the light's diffuse multiplier. `sampleClosure` returns its continuation: a delta event when the pdf is 0, no refraction or medium tracking, roughness 1 for diffuse/SSS events and 0.5 otherwise.
  - `MaterialDesc::external` (`ExternalBinding`): the shader, per parameter its input-block slot or a uniform value, string values, VEX's bounce bits.
- **Pass C** (`core/integrator/wavefront.cpp`):
  - `chooseLight()` now draws NEE's light for `shadeHit` and for `runExternal()`, which runs the bridge once per chunk of an external material before shading.
  - Lanes: P, I, N, Ng, s/t = barycentrics, dPds/dPdt = a tangent frame around N, the light direction and `stream::kBsdf`'s x, y.
  - The bounce bits map to event classes (sss > volume > refract > diffuse > reflect), so limits, Russian roulette and ray cones work unchanged.
  - External closures skip fake caustics (D13). A failed run leaves the chunk black; the bridge reports it once on stderr.
- **Hydra** (`hydra/material/vexBridge.{h,cpp}`):
  - `nova_cvex.dll` is loaded from the directory of the module holding hdNova's code (hdNova.dll; nova_cli.exe and nova_hydra_tests.exe get a copy) or from `NOVA_CVEX`.
  - A `sourceCode` surface compiles through the bridge. A parameter program writes each float parameter as `primvar(name, fallback = the material's value or the shader's default)` into the block after the named fields, which keep their defaults; opacity is 1.
  - Value edits stay parameter edits.
  - Compile errors carry VCC's messages: they arrive through `UT_ErrorManager::Scope`, not the CVEX context.
- **Tests:**
  - `nova_cvex_tests`:
    - a white VEX diffuse in a uniform dome renders 1 ± 0.01 through the full path tracer (any depth);
    - a VEX plastic (diffuse + GGX) renders the same with light-only, BSDF-only and MIS sampling.
  - `test_hydra_vex`: a builder material binds through the bridge with its authored parameter; broken code warns with the compiler's message and falls back.
- **Performance:** opaque scenes are unchanged (cornell_rect 4.13 s, motion_blur 2.28 s, dome_sky 2.97 s, mtl_spheres 2.61 s; M4: 4.22 / 2.26 / 3.00 / 2.58).
- **Deviations / not yet:**
  - The first-hit AOVs (albedo) of external materials are black until M6.
  - Opacity and emission of VEX surfaces were not read yet (done in M5.4).

Notes on M5.4 as built:
- **Outside Houdini** (nova_cli, tests): VEX's `ggx()` and the other `cvex_bsdf` lobes name their CVEX shaders as operator library paths (`oplib:/Shop/ggx_sample?Shop/ggx_sample`). Only a process with Houdini's operator director resolves them; without one libPBR got no shader and crashed in `PBR_Custom::sampleArray`.
  - The bridge registers a `VEX_VexResolver` that serves the same shaders from `$HFS/houdini/vex/CVex/<name>.vex`, only when libOP has no director (Houdini, husk and hython resolve them themselves).
  - Creating an `MOT_Director` instead was tried and rejected: it loads every installed plugin and the user's pythonrc (HtoA, PySide) and crashes at exit.
  - Diagnosis without a debugger: a vectored exception handler printing module + offset, `dumpbin /exports /disasm` and the import table; `UT_ErrorLog::setMantraVerboseLevel` shows VEX's shader lookups.
- **Displacement through the bridge (D8):**
  - `transformDisplacement` turns a `displace` function into a CVEX function (P and N exported, the other displacement globals as parameters, no BSDF tail); `ExternalBridge::compileDisplacement` returns an `ExternalDisplacer`. The bridge's thread-local context code is shared by surfaces and displacements (`Runner`).
  - `DisplacementShader::external` runs instead of a program in `displaceMesh`: world-space P and N per point (owner-triangle rule of M4.6), the parameters' values, primvars of the parameters' names per point. The world-space offset goes back to object space and onto every motion step.
  - Hydra: a `sourceCode` shader on the `vex` displacement terminal becomes the material's displacement (hash over code, values and primvar names), for builder surfaces and Principled surfaces alike. Code that does not compile warns and renders undisplaced.
- **Scopes:** the transformed body sits in a block of its own, so its locals shadow the globals-turned-parameters as they shadow VEX's globals (the Principled Shader Core declares a local `Ce`). An early `return` in a surface body skips the BSDF tail (black; not seen in builder code).
- **Primvar binding (D10):** a parameter reads the primvar of its name, or the `varname` of a `UsdPrimvarReader` connected to it (surfaces and displacements).
- **Ray tracing (D5):** a body that calls `trace`, `gather`, `illuminance`, `rayhittest`, `fastshadow`, `irradiance` or `occlusion` fails the transform with a message; the material renders its preview (husk: one warning).
- **Opacity and emission (D9):**
  - `Ce` is a surface global; its value is the hit's emission.
  - A shader whose body never names `Of` is opaque at no cost. Otherwise `makeMaterialRecord` probes it at 2 × 64 random points (the material's values, then random parameter values, since primvars may replace them per hit). One value everywhere is the material's uniform opacity. Anything else is evaluated per candidate hit in the opacity filter: the parameter program and a one-lane bridge run.
  - Deviation from D9 ("probeOutput(Of)"): CVEX reports every output as varying once the inputs are bound varying, so the probe is numeric. A texture whose holes all 128 points miss passes as uniform.
